### 1、浮点数在计算机中的表示

| 类型               | 位数 | 组成                                     |
| ------------------ | ---- | ---------------------------------------- |
| `float`（单精度）  | 32位 | 1位符号位 + 8位指数 + 23位尾数（有效数） |
| `double`（双精度） | 64位 | 1位符号位 + 11位指数 + 52位尾数          |
| `half`（半精度）   | 16位 | 1位符号位 + 5位指数 + 10位尾数           |

### 2、单精度浮点数

1. **符号位**：负数 → `1`
2. **整数部分转二进制**：5 → `101`
3. **小数部分转二进制**：0.75 → `0.11` （因为 0.75×2=1.5 → 取整数1，余0.5；0.5×2=1.0 → 取整数1）
4. **二进制科学记数法**：`5.75` → `101.11` → `1.0111 × 2^2`
5. **指数加偏移量**：单精度偏移量为 127 → 指数 = 2 + 127 = 129 → 二进制 `10000001`
6. **尾数**：小数部分 `01110000000000000000000`（补齐到23位）。

### 3、偏移量

- 存储的指数位要+127
- 实际的要 -127

| 实际指数 | 存储二进制 e = E + 127    |
| -------- | ------------------------- |
| -2       | -2 + 127 = 125 → 01111101 |
| 0        | 0 + 127 = 127 → 01111111  |
| 1        | 1 + 127 = 128 → 10000000  |
| 2        | 2 + 127 = 129 → 10000001  |

**问题来了**：硬件想直接用二进制大小比较浮点数，会出错。

- 因为补码的二进制表示是为了加减运算方便，不是为了大小比较方便。
- 比如按无符号数比较：11111110 > 00000010 > 00000000 → 实际 -2 < 2 < 0，顺序完全错。

### 4、FP32、FP16、BF16

就是存储结构不同、指数位和尾数位不同，这样导致浮点数的范围不同、精度不同

| 类型                   | 位数 | 符号位 | 指数位 | 尾数位 | 精度 | 特点                                                     |
| ---------------------- | ---- | ------ | ------ | ------ | ---- | -------------------------------------------------------- |
| FP32（单精度 float）   | 32   | 1      | 8      | 23     | 高   | 标准 IEEE 754 单精度浮点数                               |
| FP16（半精度 float）   | 16   | 1      | 5      | 10     | 中   | 更小存储空间，常用于嵌入式、显存敏感场景                 |
| BF16（Brain Float 16） | 16   | 1      | 8      | 7      | 中低 | 保留 FP32 的指数位，减少精度但范围大，常用于 AI 训练推理 |

### INT32和FP32对比

- 但是FP32的指数位是指数增长的
- 然后用尾数位来填补指数位的空缺，比如原本是0-1-2-4这里缺3实际上是由尾数位来补充的

**上面只是一种理解方式，但是实际上就是一种规则，用了同样的bit位但是不同的规则而已**
