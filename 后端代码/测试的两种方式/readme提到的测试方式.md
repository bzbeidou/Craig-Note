### 1. sgdnn 方式测试算子

- **目标**：这种方式主要是通过 **`sgdnn`** 来测试算子功能。SGDNN 是一个相对封装较高的测试框架，专门用来测试深度学习算子（如卷积、池化、激活函数等）在 TPU 上的执行情况。它通常包括：

	- **更高层的抽象**：`sgdnn` 通常会提供一层封装，使得你不需要关心底层硬件实现，能够以更高的抽象层次来测试算子功能。
	- **依赖 `sgdnn_tmp` 库**：该测试方法使用的是 `sgdnn_tmp` 库，而不是直接使用底层硬件相关的库（如 `bmlib` 和 `tpu_kernel`）。
	- **不涉及底层硬件细节**：在这种方式下，测试主要关注算子的正确性和高层 API 的稳定性，不需要考虑底层硬件（如内存管理、指令生成等）如何实现。
	- **编译和测试**：在编译时，`sgdnn_tmp` 库会被打包到应用程序中。测试框架会调用 `sgdnn` 提供的接口，运行各种算子计算，结果主要验证这些算子的正确性。
	
	**优点**：
	
	- 高层抽象，便于测试算子的功能。
- 可以快速验证算子实现是否正确，不需要深入底层硬件实现。
	

**缺点**：
	
	- 无法测试硬件层面的细节，如指令调度、内存管理、数据传输等。
- 依赖 `sgdnn_tmp` 库，可能不适用于某些特殊的硬件调优或性能测试。

### 2. **底层代码**

- **目标**：这种方式使用底层硬件相关的代码来测试 TPU 计算，包括指令生成、硬件调度等。底层代码（如 `atomic_xxx_gen_cmd` 系列函数）负责直接操作硬件资源并生成 TPU 执行的指令。测试的主要目的是验证底层硬件的功能、效率和稳定性。

	- **涉及底层硬件细节**：在这种方式下，你将直接与底层硬件库（如 `bmlib`、`tpu_kernel` 等）进行交互，进行低级别的硬件指令生成、数据传输等操作。
	- **编译和测试**：测试时，只使用底层代码库，如 `atomic_xxx_gen_cmd` 系列函数来调度硬件执行。通过这种方式，可以验证底层硬件的运行状态。
	- **测试过程**：
		- 使用 `-DUSING_CMODEL_TEST=ON` 选项进行 CMake 构建。
		- 编译时，测试程序会链接到底层硬件库，不依赖 `sgdnn` 或其他高级框架。
		- 执行 `rebuild_test cmodel` 或 `build_test cmodel` 来编译并运行测试。

	**优点**：

	- 可以深入了解 TPU 硬件的实现细节。
	- 测试更接近硬件，可以验证硬件指令生成、内存管理、指令调度等底层功能。

	**缺点**：

	- 编写和运行测试更复杂，需要关注硬件细节。
	- 可能需要额外的硬件调试和性能优化。

- **高层抽象 vs. 低层硬件操作**：
	- `sgdnn` 测试框架提供的是较高层次的抽象，专注于算子层面的测试，便于测试算子功能是否正确。
	- 只使用底层代码测试则专注于硬件层面的实现，测试硬件如何执行指令和调度操作，验证硬件功能和性能。
- **编译方式**：
	- `sgdnn` 方式底层硬件相关的实现被抽象化。
	- 只使用底层代码方式则依赖于硬件相关库，如 `bmlib`、`tpu_kernel` 等，直接操作硬件。
- **适用场景**：
	- `sgdnn` 测试适合快速验证算子是否正确执行，而无需关心硬件细节。
	- 只使用底层代码的测试则适合验证硬件实现的正确性，特别是在硬件调度、指令生成等底层功能上。

### 3. **测试执行的差异**

- **`sgdnn` 测试**：
	- 测试算子正确性。
	- 需要 `-DUSING_SGDNN_TEST=ON` 选项。
	- 通过 `rebuild_test sgdnn` 编译测试。
- **底层代码**：
	- 测试硬件指令和底层实现。
	- 需要 `-DUSING_CMODEL_TEST=ON` 选项。
	- 通过 `rebuild_test cmodel` 编译测试。



虽然 `sgdnn` 本身是一个较高层次的测试框架，专注于验证深度学习算子的正确性，但它在内部确实依赖于底层代码来执行实际的硬件操作。因此，`sgdnn` 最底层还是会调用底层硬件相关的代码来执行运算任务，具体来说，`sgdnn` 内部的操作最终会转化为对 TPU 硬件的指令调用。这就像是一个中间层，它将复杂的硬件操作进行了封装，暴露出一个简化的接口供用户使用。

具体过程

1. **高层**：
	- 在使用 `sgdnn` 测试时，用户关注的主要是高层的深度学习模型或算子。用户编写的测试代码通常通过调用 `sgdnn` 提供的 API 来进行模型训练或推理。
	- 这些 API 主要聚焦于卷积、池化、全连接等操作，而不需要用户直接操作 TPU 的硬件层细节。
2. **底层调用**：
	- 在 `sgdnn` 执行计算时，它会依赖底层的 `bmlib`、`tpu_kernel` 等库，这些库负责与 TPU 硬件直接交互，生成硬件可以执行的指令。
	- 例如，当进行卷积运算时，`sgdnn` 可能会调用底层的 `nodechip_conv_float_parallel` 或其他类似函数，这些函数会进一步调度硬件资源，生成指令，执行数据传输、内存管理等底层操作。
3. **指令生成**：
	- 在 `sgdnn` 内部，执行某些操作（如卷积、激活函数）时，可能会调用像 `atomic_conv_gen_cmd` 这样的底层函数来生成相应的硬件指令。最终，这些指令会被发送给 TPU 执行。
	- `atomic_conv_gen_cmd` 函数本身就是负责生成与硬件相关的指令，它会根据输入的参数生成对应的操作指令，并调度硬件资源进行执行。
4. **硬件执行**：
	- 经过底层代码生成的指令会被传输到 TPU 上，并由硬件执行。这一过程包括数据从主机内存传输到 TPU 内存、在 TPU 上执行计算、并将结果返回。
