# 向量浮点加法微指令执行过程分析及 CODE 位长度说明

## 一、向量浮点加法完整执行过程（基于样例）

整个过程围绕 “数据读取→数据转发→计算→结果回写” 四大核心步骤，涉及 UR（用户寄存器）、RtoVR（数据通路）、FPADD（浮点加法器）三个模块的协同，通过 SMI-IQ 微指令队列有序驱动，具体流程如下：

### 1. 初始化与指令加载

- 系统复位后，SMI 将各模块对应的微指令写入专属 IQ（指令队列），每个 IQ 仅存储对应模块的控制指令，确保指令执行的独立性和针对性。
- 本例中所有 IQ 的指令长度均为 2 条（地址 0：执行指令，地址 1：结束指令），LOOPS 字段均设为 16，对应 16 组 128bit 数据的批量处理。

### 2. 数据读取阶段（UR 模块驱动）

- **UR-R0 微指令执行**：地址 0 指令（VLD=1、LOOPS=16）触发 UR Bank0 连续读取 16 行数据，通过 UR-RDATA-0 端口输出，目标是输入 0 数据（对应 FPADD 的 DVR-FPADD-S0 接口）。
- **UR-R1 微指令执行**：与 UR-R0 并行，地址 0 指令（VLD=1、LOOPS=16、INC=1）触发 UR Bank1 连续读取 16 行数据，通过 UR-RDATA-1 端口输出，目标是输入 1 数据（对应 FPADD 的 DVR-FPADD-S1 接口）。
- 关键细节：INC=1 仅用于 UR-R1 的地址自增，确保连续读取 Bank1 的不同行数据，UR-R0 因读取连续地址无需自增（INC=0）。

### 3. 数据转发阶段（RtoVR 模块驱动）

- 两组 RtoVR 微指令并行执行，地址 0 指令（VLD=1、DLY=1）负责将 UR 输出数据转发到 FPADD 输入接口：

	- 第一组 RtoVR：将 UR-RDATA-0 的数据转发至 DVR-FPADD-S0。
	- 第二组 RtoVR：将 UR-RDATA-1 的数据转发至 DVR-FPADD-S1。

	

- 关键细节：DLY=1 是因为 UR 读取数据需要 1 个时钟周期，延迟 1 拍可确保转发数据的有效性，避免数据提前到达导致的计算错误。

### 4. 浮点加法计算阶段（FPADD 模块驱动）

- FPADD 微指令地址 0 指令（VLD=1、DLY=2、CODE={1,1,1,0}）触发 16 次浮点加法：

	- DLY=2 的原因：UR 读取（1 拍）+ RtoVR 转发（1 拍），共 2 拍延迟，确保 FPADD 接收到有效输入数据后再启动计算。
	- CODE 字段解析：{1,1,1,0} 对应 4 个微指令位，分别表示 “指令有效（1）、源寄存器精度 32bit（1）、目的寄存器精度 32bit（1）、不更新状态寄存器（0）”，完全匹配 FPADD 的微指令格式要求。

	

- 计算逻辑：每组 128bit 数据按 32bit 分组（4 组 / 行），并行执行 4 个 FPADD 加法器，输出结果存储至 DR-FPADD-D 寄存器。

### 5. 结果回写阶段（UR 模块驱动）

- 第三组 RtoVR 微指令（DLY=3）：将 FPADD 的计算结果（DR-FPADD-D）转发至 UR 的 UVR-WDATA-0 端口。
- UR-W0 微指令地址 0 指令（VLD=1、DLY=4）：将转发后的结果写入 UR Bank2 的连续 16 行地址，完成整个数据处理闭环。
- 关键细节：DLY=4 是因为计算（1 拍）+ 结果转发（1 拍），累计 4 拍延迟，确保结果正确回写至 UR。

### 6. 结束阶段

- 所有 IQ 地址 1 的指令（JUMP=1、CODE=0）触发跳转，标志当前子队列指令执行结束，反馈 RDI_DONE 信号给 SMI。

## 二、CODE 位长度说明

### 1. 核心结论：CODE 位长度 “场景化确定”，无固定全局值

文档中未定义统一的 CODE 位长度（BITS_CODE 字段无具体数值），但根据模块特性和样例可推导：**CODE 位长度由对应模块的微指令格式决定，不同模块的 CODE 位长度不同**，本质是 “按需分配” 以节省指令存储空间。

### 2. 各模块 CODE 位长度推导（基于样例和微指令格式）

|      模块      |  CODE 位长度  |                           推导依据                           |
| :------------: | :-----------: | :----------------------------------------------------------: |
| UR（R0/R1/W0） | 可变（≥8bit） | 以 UR-R0 为例，CODE 包含 {ur-rbank-0（3bit，8 个 Bank）、ur-raddr-0（8bit，256 个地址）、ur-re-0（1bit）}，合计≥12bit，样例中简化为字段组合表示 |
|     RtoVR      |     10bit     | CODE 包含 {mv_out?_vld（1bit）、mv_out?（5bit，支持 32 个输入源编码）}，合计 6bit，预留 4bit 扩展，实际≥6bit |
|     FPADD      |     4bit      | 样例 CODE={1,1,1,0}，对应 4 个微指令位（指令有效、源精度、目的精度、状态更新），与 FPADD 微指令格式的 4bit 长度完全匹配 |

### 3. 关键说明

- CODE 位长度的设计原则：仅包含模块所需的控制信息，不冗余分配位宽，例如 FPADD 无需地址控制，仅需 4bit 即可满足需求；UR 需地址、Bank 选择等控制，位宽自然更长。
- 样例中 CODE 以 “字段组合” 形式呈现（如 {ur-rbank-0, ur-raddr-0, ur-re-0}），本质是对具体 bit 位的功能描述，实际存储时按模块的 BITS_CODE 参数固化为二进制位流。
