```bash
ls /dev/bm*
/dev/bmdev-ctl  /dev/bm-sophon0  /dev/bm-sophon1  /dev/bm-sophon2
```

说明系统检测到了 3 个 BM1684X 算力卡设备，设备节点存在，这是硬件层面正常的信号

- 驱动/内核消息

```bash
dmesg | grep BMRT
# 没有输出
```

驱动没有报错，但也没有输出 BMRT 初始化信息。

结合之前 Python 运行时提示 `device X failed to enable on-chip CPU`，说明驱动虽然加载了，但板载 CPU 模块 **没有正常启用**。

对于普通推理（非 bmcpu_opencv 功能）可以忽略，但如果示例依赖 bmcpu_opencv，就会出问题。

- Python sail 模块

```bash
python3 -c "import sophon.sail; print(dir(sophon.sail))"
```

可以成功 import `sophon.sail`，说明 Python 包安装没问题。

但 `get_version()` 不存在，确认版本不支持这个方法, 这个不重要，忽视。

可以看到包含 `Engine`, `Tensor`, `Bmcv`, `Decoder` 等方法，基本的推理功能是可用的。



#### 2、可能的原因

- 权限问题

虽然给 `bmodel` 权限是 `-rwxrwxrwx`，但是加载到芯片需要访问 `/dev/bm-*` 设备。

如果你不是 root 或者用户组权限不足，会导致加载失败。



- 用户空间CPU模块未启用

```
device 0 failed to enable on-chip CPU! If not using bmcpu_opencv function, please ignore it.
```

说明芯片上的 on-chip CPU 不能启动，可以暂时忽略

- **BMRT 依赖的 `.so` 文件缺失或路径问题**

错误里提到 `c33e24ae88a6427f97afcc92.so`。

这个文件一般在 `/usr/lib/bm` 或 SOPHONSDK 的 runtime 目录下。

如果 SDK 没有正确安装或者 `LD_LIBRARY_PATH` 未设置，BMRT 找不到文件。

**目前最可能的原因是是BMRT 在加载 bmodel 到芯片时失败**



#### 3、新进展

这里是通过`test1.py`来获得到的信息

```
tpu-mlir@tpumlir-Z390-UD:~/tpu-mlir/sophon-demo_v0.3.2_75528cb_20250714/sample/ResNet$ find /opt/sophon -name "libbmrt.so" 2>/dev/null
/opt/sophon/libsophon-0.5.1/lib/libbmrt.so
```

**确认BMRT 已经装好了**,否则根本不会打印 `[BMRT][preload_funcs]` 的日志，也不会进入加载流程。

真正的问题在于：

> 模型加载阶段，BMRT 尝试在 TPU 上加载内核模块时失败了。

在加载 `.bmodel` 的过程中，出现了“加载 usercpu.so 失败”的错误

```
open usercpu.so, init user_cpu_init 
[a53lite_runtime][error] copy from system to device for file c33e24ae88a6427f97afcc92.so error, ret = 2
[a53lite_runtime][error] ../bmlib/src/a53lite_api.cpp 568: load file failed!
[BMRT][preload_funcs:2145] FATAL:BMRT_ASSERT: _kernel_modules[core_id]
[error] Load models/BM1684X/resnet50_fp32_1b.bmodel failed
```

- 日志解释：

| 日志                                            | 含义                                                 |
| ----------------------------------------------- | ---------------------------------------------------- |
| `open usercpu.so, init user_cpu_init`           | 运行时尝试加载 CPU 辅助算子库（用于非 TPU 算子执行） |
| `copy from system to device ... error, ret = 2` | 无法把相关库文件加载到设备（TPU 芯片）中             |
| `BMRT_ASSERT: _kernel_modules[core_id]`         | BMRT 在加载 bmodel 时断言失败（未能初始化 TPU 核心） |
| `Load bmodel failed`                            | 模型未能正确加载                                     |

**这里有一个关键问题就是无法将相关库文件`c33e24ae88a6427f97afcc92.so`加载到设备**



这里通俗解释一下就是bmodel中的某些部分会被bmrt给变成.so，然后名称就是这种哈希值的表现，这里要么就是转换成.so文件根本没成功，要么就是将其加载到芯片失败

**可能是以下问题：**

| 原因                          | 含义                                                      | 解决建议                     |
| ----------------------------- | --------------------------------------------------------- | ---------------------------- |
| 驱动没加载                    | TPU 没准备好，BMRT 无法传文件                             | 运行 `sudo modprobe bm1684x` |
| 权限不足                      | 普通用户不能访问 `/dev/bm-sophon0`                        | 用 `sudo python3` 运行脚本   |
| `.bmodel` 与 libsophon 不匹配 | 比如用的 bmodel 是 0.4.x 编译的，但系统是 libsophon-0.5.1 | 统一版本（模型和 SDK 一致）  |
| 芯片不匹配                    | BM1684 的模型放在 BM1684X 芯片上跑                        | 换用匹配的 bmodel            |
