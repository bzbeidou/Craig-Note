从这个输出视角看可以看成一个立方体的样子：

## 引
硬件、编译器、性能分析里，会进一步把：“为了得到整个输出，一共做了哪些乘加？”

画成一个三维的计算空间。

先抓住一句话：$$ \boxed{M,N\text{决定输出位置，}K\text{决定每个输出位置内部要累加多少次}} $$

这就是为什么经常把 MN 看成一个整体平面，而 K 看成第三个方向。

## 1、最熟悉的矩阵乘

假设：

$$ A[M,K]\times B[K,N]\rightarrow C[M,N] $$

其中某一个输出元素：

$$ C_{m,n} = \sum_{k=0}^{K-1} A_{m,k}B_{k,n} $$

例如：$$ M=2,\quad N=3,\quad K=4 $$

那么结果矩阵 C 是：

$$ C= \begin{bmatrix} C_{0,0} & C_{0,1} & C_{0,2}\\ C_{1,0} & C_{1,1} & C_{1,2} \end{bmatrix} $$

一共：$$ M\times N=2\times3=6 $$个输出元素。

所以你可以先把 **M 和 N 看成输出矩阵的两个坐标轴**：

```
                 N
          0      1      2
       ┌──────┬──────┬──────┐
 M = 0 │ C00  │ C01  │ C02  │
       ├──────┼──────┼──────┤
 M = 1 │ C10  │ C11  │ C12  │
       └──────┴──────┴──────┘
```

这就是所谓：$$ \boxed{M\times N\text{ 是输出平面}} $$    所以很多资料会把 MN 放在一起讲。

## 2、那 K 去哪了？

上面每一个小格，比如：$$ C_{0,1} $$

不是一次乘法得到的。

其实是：

$$ C_{0,1} = A_{0,0}B_{0,1} + A_{0,1}B_{1,1} + A_{0,2}B_{2,1} + A_{0,3}B_{3,1} $$

因为：$$ K=4 $$

所以这个输出元素背后有 4 次乘法，然后累加起来。

k=0: A00 ×B01 ─┐
k=1: A01 × B11 ─┤
k=2: A02 × B21 ─┼── SUM ──> C01
k=3: A03 × B31 ─┘

因此一个输出其实不仅仅是一个MAC，而是一串沿 K 方向的计算。这就是第三个维度 K 出现的原因。

## 3、所谓 M-N-K 立方体到底是什么

可以把它画成：

```
                 K
                /
               /
              /
     ┌───────────────┐
    /               /|
   /               / |
  ┌───────────────┐  |
  │               │  |
M │   计算空间     │  |
  │               │  ┘
  │               │ /
  └───────────────┘
          N
```

所以这个立方体表示的不是数据矩阵，而是：整个 MatMul 的计算空间

## 4、为什么硬件的人特别喜欢 M-N 平面

对于硬件来说，最自然的问题就是：我一次能并行生成多少个输出元素？

例如某一个矩阵计算单元一次负责：$$ 16\times16 $$个输出。

那么它负责的就是一个：$$ M_{\text{tile}}\times N_{\text{tile}} $$平面：

```
             N = 16
       ┌────────────────┐
       │                │
       │    C tile      │
M=16   │     16×16      │
       │                │
       └────────────────┘
```

但每一个输出都需要沿 K 累加。

例如：$$ K=64 $$

那么：

```
16×16 个 output
       ×
每个 output 64 个 MAC

```
总共：$$ 16\times16\times64 $$个 MAC。

**硬件资料自然就会把工作量描述成：M×N×K**

## 5、这就是为什么 FLOPs 是 2MNK

矩阵乘：$$ [M,K]\times[K,N] $$

总共有：$$ M\times N $$个输出。

每个输出需要：$$ K $$次乘法。

所以总乘法次数：$$ MNK $$     以及近似：$$ MNK $$次加法。

于是：$$ \boxed{\text{FLOPs}\approx2MNK} $$

$$ M\times N\times K $$其实就近似代表：矩阵乘的总计算量。所以这种立方体画法在性能分析里特别常见。

## 6、和 Tensor Core / Cube Unit 有什么关系

比如一个硬件矩阵指令：$$ m16n16k16 $$这种命名方式，含义不是输出一个 16×16×16 Tensor。

而是：$$ A[16,16]\times B[16,16] $$

也就是：output tile:16 × 16

reduction depth: K = 16
