## 一、三个问题

| 问题                   | 答案                                                         |
| ---------------------- | ------------------------------------------------------------ |
| cube 是什么            | **矩阵/卷积类运算的专用计算单元**——一个每时钟能完成“一块三维 MAC 运算体”的硬件阵列 |
| 是通用设计概念吗       | **概念是通用的**（专用矩阵计算阵列，所有 AI 芯片都有），但各家实现方式不同 |
| “cube”是业界通用说法吗 | **是真实存在的行业用词，但不统一**。最著名的是华为昇腾的 Cube Unit；同类东西 NVIDIA 叫 Tensor Core、Google TPU 叫脉动阵列（systolic array）。 |

## 二、本仓库里的 cube：精确定义

### 1. cube 的“形状”是被显式定义的硬件属性

`bm1684x/spec/include/base_def.h:86`：

```
#define GET_CUBE_IC_PARALLEL(prec) \
  ((prec == INT8) ? 64 : \
   (prec == FP16 || prec == BFP16) ? 32 : 1)

#define GET_CUBE_W(prec) (4)
```

并且通过 tpu_kernel API 对外暴露（`tpu_kernel.h:332`）：

```
dim2 tpu_cube_shape(data_type_t dtype);   // 返回 {输入通道并行度, W方向宽度}
```

对 FP16 就是 `{32, 4}`——**每条 lane 每周期处理 32 个输入通道 × 4 个空间位置**。

### 2. cube 和 vector 在本芯片词汇表里是并列的两个词

`bm1684x/spec/include/config.h:23`：

```
#define CUBE_COMPUTILITY    24    //for EU_NUM_8BIT   ← 矩阵/卷积类
#define VECTOR_COMPUTILITY   4    //for EU_NUM_8BIT   ← 逐元素类
```

`tpu_kernel.c:210` 还封装成了查询接口 `tpu_cube_computility(dtype)`。**这不是我发明的说法，是芯片设计者自己的命名。**

### 3. cube 形状是“每代芯片的设计参数”

对比下一代芯片（`bm1686/spec/include/base_def.h:99`）：

|            | bm1684x | bm1686              |
| ---------- | ------- | ------------------- |
| INT4       | —       | 64 通道             |
| INT8       | **64**  | 32                  |
| FP16/BFP16 | **32**  | 16                  |
| FP32       | 1       | 1                   |
| W 宽度     | 4       | INT4/INT8→4，其他→2 |

**cube 的尺寸在两代芯片之间变了**——它就像核数、缓存大小一样，是每代芯片架构定义的一部分。这进一步证明它是正式的架构概念，不是随口的比喻。

### 4. 哪些指令“走 cube”

| 走 cube 数据通路                                             | 不走 cube                                    |
| ------------------------------------------------------------ | -------------------------------------------- |
| **CONV**（我们逆向的周期公式就是 cube 模型）                 | **mm**（矩阵模式，另一条 FP32 数据流）       |
| **MM2**（GEMM 模式，cycle 公式与 CONV 逐项同构，共用 `ADDTREE_NUM = GET_CUBE_IC_PARALLEL`） | **AR**（张量算术=向量运算）、SFU（特殊函数） |

## 三、几何直觉：为什么叫 "cube"（立方体）

看矩阵乘的定义：

```
C[M, N] = Σ(k=0..K-1)  A[M,k] × B[k,N]
```

这是一个**三层嵌套循环**（M、N、K）。把每一对 (m, n, k) 的乘加想象成三维空间里的一个点，整个 GEMM 的计算量就是一个 **M × N × K 的三维长方体**。

**硬件每周期完成这个三维体中的一小块——这个“块”就是 cube。**

## 四、cube / vector / scalar：AI 芯片的“三件套”（通用设计模式）

本芯片和昇腾的对照（你会发现结构同构到令人愉快）：

| 计算类型                     | 本芯片（BM1684X）                                 | 华为昇腾（达芬奇） | NVIDIA          |
| ---------------------------- | ------------------------------------------------- | ------------------ | --------------- |
| **矩阵/卷积（cube 类）**     | BD 引擎的 CONV / MM2 指令                         | **Cube Unit**      | Tensor Core     |
| **向量/逐元素（vector 类）** | AR 指令（张量算术：加/乘/最大…）+ SFU（sqrt/exp） | **Vector Unit**    | CUDA Core + SFU |
| **标量/控制**                | 固件 MCU（调度、循环、地址计算）                  | **Scalar Unit**    | CPU             |

为什么必须有这个分工？因为两类算子的计算结构完全不同：

- **规约型**（conv/matmul）：大量乘加**求和归约**，操作数高度复用 → 需要 MAC 阵列 + 加法树（cube）；
- **逐元素型**（ReLU、BN、add）：每个元素独立算，无归约、无复用 → 需要宽向量通路（vector），cube 干这个反而浪费。

这就是 `CUBE_COMPUTILITY=24` 和 `VECTOR_COMPUTILITY=4` 并列存在的意义——**芯片同时装备两种算力的队伍**，固件按算子类型选引擎。



## 五、G W是什么？

## {G, W} 片（tile）：每条车道一次啃多大一块

每条 lane 每个时钟周期能**同时**处理一个矩形的小数据块，这个块的大小就是 `{G, W}`，注意这里不是输出，而是指的是K维上的计算：

- **G**（FP16 时 = 32）：一次同时处理 **32 个输入通道**，也就是K维32个数；
- **W**（恒为 4）：一次同时处理 **4 个位置**（4 个像素或 4 列）。

所以每条 lane 每周期同时做 **32 × 4 = 128 次乘法**

64 条 lane 加起来：**64 × 128 = 8192 次乘法/周期**。这就是我们反复看到的那个"8192 MAC/cycle"的来历。

代码里的对应（`base_def.h`）：

```
#define GET_CUBE_IC_PARALLEL(prec)  (FP16 → 32)   // ← 这就是 G
#define GET_CUBE_W(prec) (4)                        // ← 这就是 W
dim2 tpu_cube_shape(dtype);                         // ← 返回 {G, W}
```

"tile"（切片/块）这个叫法的含义就是：**把大任务切成一托盘一托盘的小块，每周期消化一托盘**。你之前听过的“tiling / 切分”，就是上层软件在决定“怎么切才能每托盘都装满”。

## G宽加法树（adder tree）

上面提到G次乘法，当然也要相加，相加的就是G个数G-1次加法，叫做G宽加法树

## 六、本地 / 广播操作数：两种数据怎么送到 64 条车道

最核心的一条。参与乘法的**两个操作数**，**运送方式完全不同**：

### 本地（local）：放在自家，不出门

- 做卷积时：**lane 5 算输出通道 5，通道 5 的全部权重就存在 lane 5 自己的 256KB 里**，永远不搬家；
- 做矩阵乘时：**lane 5 算输出第 5 行，第 5 行的输入数据就存在 lane 5 本地**。

**零搬运成本**，每周期从自家内存读一行就用。

### 广播（broadcast）：一份发所有人。

- 做卷积时：**输入数据**（比如第 37 号通道的一个像素值）**读一次，同时发给全部 64 条 lane**——因为每一条 lane 算自己的输出通道时，都需要所有输入通道的值；
- 做矩阵乘时：**R 矩阵**（权重）广播给全部 lane。

**读一次，用 64 次**——这就是“数据复用”，是这类芯片算力爆表的秘密。搬运成本 1/64。

原句：“（64 lane × {G,W} 片 + G 宽加法树 + 本地/广播操作数模式）”

大白话版：**“64 个npu，每个npu每个周期同时算一个 32×4 的小数据块；算出的 32 个乘积 5 轮加成一个数；两个乘数里，一个（权重）各条线自己存着不动，另一个（输入）读一次广播给全部 64 条线。”**
