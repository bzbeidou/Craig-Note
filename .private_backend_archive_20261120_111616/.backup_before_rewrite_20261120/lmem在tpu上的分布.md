LMEM 是计算单元旁边、由软件管理的高速 SRAM；Lane/NPU 决定“哪个通道处理数据”，Bank 决定“这块 SRAM 能否同时服务多次访问”。

## 1. LMEM 在整个架构中的位置

1. GDMA 把输入、权重从 DDR 搬到 LMEM。
2. TIU 从 LMEM 取数计算。
3. 结果先写回 LMEM。
4. GDMA 再把结果搬回 DDR。

因此卷积代码里经常能看到：

```
S2L：DDR → LMEM
BDC/TIU：在 LMEM 上计算
L2S：LMEM → DDR
```

## 2. BM1684X 的 LMEM 结构

| 层级                  | 数量       | 容量                              |
| --------------------- | ---------- | --------------------------------- |
| Lane / NPU            | 64         | 每个 Lane 256 KiB                 |
| Bank                  | 16         | 每个 Lane 中每个 Bank 对应 16 KiB |
| 整个 TPU Core 的 LMEM | 64 个 Lane | 16 MiB                            |

关系是：

```
一个 TPU Core
├── Lane/NPU 0：256 KiB
│   ├── Bank 0：16 KiB
│   ├── Bank 1：16 KiB
│   └── ...
│       Bank 15：16 KiB
├── Lane/NPU 1：256 KiB
└── ...
    Lane/NPU 63：256 KiB
```

从物理图看，也可以把它理解为 **16 条 Bank，每条 Bank 横跨 64 个 Lane**：

```
                 Lane0    Lane1   ...   Lane63
Bank 0           16KB     16KB          16KB
Bank 1           16KB     16KB          16KB
...
Bank 15          16KB     16KB          16KB
```

所以有时文档说“LMEM 有16个 Bank”，有时我们又说“每个 Lane 的地址空间分成16个 Bank 区域”，说的是同一件事的两个观察角度。编程文档中的原始结构图在[这里 (line 432)](C:/Users/sherlock/Desktop/instruction/TPU1686_origin/doc/common/tpu_kernel/source/usage/3_TPU编程和运行模型.rst:432)。

CModel 也确实分配了 `LOCAL_MEM_SIZE × NPU_NUM`，然后切成64片 Lane 内存

## 3. 一个 LMEM 地址怎样拆成 Lane 和 Bank

BM1684X 默认每个 Lane 为 `2^18 = 256 KiB`，一共有 `2^6 = 64` 个 Lane。统一 LMEM 地址可以理解为：

```
| 6 bit Lane编号 | 4 bit Bank编号 | 14 bit Bank内偏移 |
|    [23:18]     |    [17:14]     |      [13:0]      |
```



## 4. EU、Lane 和 Bank 的区别

这三个概念很容易混：

| 概念     | 主要作用                      |
| -------- | ----------------------------- |
| Lane/NPU | 并行处理不同 Channel          |
| EU       | 一个 Lane 内并行处理 H/W 数据 |
| Bank     | 提供 SRAM 访存带宽            |

每个 Lane 的有效 EU 数量随数据宽度变化：

- FP32/INT32：16个元素
- FP16/BF16/INT16：32个元素
- INT8：64个元素

它们正好都是一组64字节：

```
16 × 4 字节 = 64 字节
32 × 2 字节 = 64 字节
64 × 1 字节 = 64 字节
```

所以 BM1684X 的 aligned layout 会把一个 Channel 的 `H×W` 空间补齐到64字节的整数倍。

例如 `H×W=20`：

| 类型 | Compact 的 C_stride | Aligned 的 C_stride |
| ---- | ------------------- | ------------------- |
| INT8 | 20元素/20B          | 64元素/64B          |
| FP16 | 20元素/40B          | 32元素/64B          |
| FP32 | 20元素/80B          | 32元素/128B         |

Aligned 会浪费一点空间，但取数更规整，通常更适合计算单元。

## 5、什么是bank？

### （1）为什么要有bank

让计算单元能够在同一时间读取多个操作数、写入结果，而不是所有访问都挤在同一块 SRAM 上排队。

假设整个 LMEM 只有一块巨大的 SRAM：

```
         ┌─────────────┐
输入A ──→│             │
输入B ──→│  一整块SRAM  │──→ 输出
结果  ──→│             │
         └─────────────┘
```

一次向量运算可能同时需要：

```
result = A + B
```

这意味着同一个周期最好完成：

```
读 A
读 B
写 result
```

如果 SRAM 同一时间只能处理有限次数的读写，那么访问就要排队，计算单元会空等。

于是硬件把 LMEM 拆成多个 Bank：

```
┌──────── Bank 0 ────────┐
├──────── Bank 1 ────────┤
├──────── Bank 2 ────────┤
│          ...            │
└──────── Bank 15 ───────┘
```

不同 Bank 有各自的地址译码、存储阵列和访问控制，因此可以一定程度上并行工作：

```
读 Bank 0 中的 A
读 Bank 1 中的 B
写 Bank 2 中的 result
```

### （2）Bank 仅仅是 SRAM 的物理组织方式。

从软件角度看，你仍然使用一个连续的 LMEM 地址：

```
地址 0
地址 1
地址 2
...
地址 262143
```

硬件根据地址判断它属于哪个 Bank。

BM1684X 中，每个 Lane 的 LMEM 是256 KiB，分成16个 Bank：

```
256 KiB ÷ 16 = 16 KiB
```

所以每个 Lane 内的地址划分如下：

| Lane 内地址范围    | 所属 Bank |
| ------------------ | --------- |
| `0x00000～0x03FFF` | Bank 0    |
| `0x04000～0x07FFF` | Bank 1    |
| `0x08000～0x0BFFF` | Bank 2    |
| `0x0C000～0x0FFFF` | Bank 3    |
| …                  | …         |
| `0x3C000～0x3FFFF` | Bank 15   |

### （3）一个完整 LMEM 地址包含什么

BM1684X 有64个 Lane，每个 Lane 有256 KiB。统一 LMEM 地址可以拆成（记住这种表示方式，越高位则代表更高的一种层级，这种表示方式确实很巧妙）：

```
┌──────────┬──────────┬────────────────┐
│ Lane编号 │ Bank编号 │ Bank内部地址    │
│  6 bit   │  4 bit   │    14 bit      │
└──────────┴──────────┴────────────────┘
   [23:18]    [17:14]       [13:0]
```

### （3）Lane 和 Bank 到底有什么区别   这是最需要分清楚的地方。

### Lane/NPU：负责计算并行   BM1684X 有64个 Lane，Tensor 的 Channel 通常轮流分到这些 Lane：

```
C0  → Lane 0
C1  → Lane 1
C2  → Lane 2
...
C63 → Lane 63
C64 → Lane 0 的下一个位置
```

所以 Lane 主要解决的是：同时计算很多 Channel。

### EU：负责一个 Lane 内的向量计算

一个 Lane 内还有多个 EU：

```
Lane 0
├── EU 0
├── EU 1
├── ...
└── EU 15/31/63
```

它们通常并行处理一个 Channel 内的 H/W 元素。

### Bank：负责供应数据

Bank 主要解决的是：同一个 Lane 内，多个操作数如何高效读写。

### （4） 什么是端口 Port

一个 Bank 不是无限并行的，它有有限的访问端口。理解成 Bank 的“服务窗口”：

```
             ┌──────────┐
读取请求1 ──→│ 读端口0   │
读取请求2 ──→│ 读端口1   │
             │  Bank     │
写入请求  ──→│ 写端口    │
             └──────────┘
```

如果一个 Bank 有两个读端口，理论上同一周期最多可以接受两次读请求。第三次读请求就可能要等下一个周期。

影响是否冲突的因素包括：

- 是否访问同一个 Bank；
- 是读还是写；
- Bank 有几个读写端口；
- TIU 和 GDMA 是否同时访问；
- 某条指令本身需要几路输入和输出；
- 读写是否可以被硬件旁路或广播。

### （5）Bank Conflict 到底是怎么发生的

以加法为例：

```
R = A + B
```

计算单元需要：

```
读取 A
读取 B
写入 R
```

### 情况一：位于不同 Bank

```
A → Bank 0
B → Bank 1
R → Bank 2
```

访问关系：

```
周期1：
Bank 0 读取 A ─┐
Bank 1 读取 B ─┼─→ EU 执行加法
Bank 2 写入 R ←┘
```

这些 Bank 相对独立，容易并行，性能通常较好。

### 情况二：A 和 B 位于同一个 Bank

```
A → Bank 0 的地址 0x0100
B → Bank 0 的地址 0x2100
R → Bank 2
```

注意，A 和 B 的地址不同，数据也没有重叠，但它们都在 Bank 0。

如果当前访问能力不足以同时读取两者，硬件可能变成：

```
周期1：从 Bank 0 读取 A
周期2：从 Bank 0 读取 B
周期3：计算或写结果
```

计算单元需要等待，这就是 Bank Conflict。

所以：Bank 冲突不等于地址重叠。两个完全不同的地址，只要处于同一个 Bank，并且需要同时访问，就可能冲突。

**在同一个 Bank”不一定总有冲突**

Bank Conflict 必须同时**满足两个条件：**

1. 访问落到同一个 Bank；
2. 这些访问在时间上重叠，而且超过了 Bank 的端口能力。

例如：

```
时刻1：读取 Bank 0
时刻2：再次读取 Bank 0
```

这是先后访问，通常没有冲突。

下面这种才可能有冲突：

```
同一个时刻：
TIU 读取 Bank 0
GDMA 也读取 Bank 0
另一个操作数还要读取 Bank 0
```

### （6）Bank Conflict 和地址覆盖不是一回事

需要区分两个问题。

### Bank Conflict：性能问题

```
A：Bank 0，地址 0x0000～0x0FFF
B：Bank 0，地址 0x2000～0x2FFF
```

A、B 数据没有重叠，但同时访问可能变慢。

### 地址覆盖：正确性问题

```
A：地址 0x0000～0x1FFF
B：地址 0x1000～0x2FFF
```

A、B 的实际存储区间发生重叠。如果写 B，就可能破坏 A。

所以：

```
同 Bank、不同地址 → 数据可以正确，但可能变慢
地址发生重叠       → 数据可能被破坏
```

部分指令允许输入和输出原地重叠，部分不允许，需要按具体指令判断。
