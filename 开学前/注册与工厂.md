### 2、注册Dialect的过程拆解

**1）首先写了一个自己的Dialect，实际上就是一个类**

```c++
class MyDialect : public mlir::Dialect {
  // 自定义内容……
};
```

**2）那么注册是什么呢？**

**就是把这个Dialect的信息先登记一下**

```c++
void registerAllDialects(mlir::DialectRegistry &registry) {
    registry.insert<MyDialect>();  // 把构造函数注册到 registry
}
```

也就是说：

- 很明显这里使用了DialectRegistry的示例对象registry的insert方法
- 实例对象 = 不立即创建，而是在需要时由 MLIR 调用这个构造函数来创建；



### 3、**注册Pass过程拆解**

**1）先写一个Pass类**

```c++
class ConvertTopToTpuPass : public mlir::Pass {
  // Pass实现内容
};
```

**2）然后注册**

```c++
mlir::registerPass([]() -> std::unique_ptr<mlir::Pass> {
  return std::make_unique<ConvertTopToTpuPass>();
});
```

这也就是一个注册，并没有创建对象，当运行了 `--convert-top-to-tpu` 这个 Pass，就调用这个 lambda 函数，返回一个新的 `ConvertTopToTpuPass` 对象。



| 项目         | Dialect 注册                     | Pass 注册                                 |
| ------------ | -------------------------------- | ----------------------------------------- |
| 目的         | 告诉 MLIR 如何识别解析你的方言   | 告诉 MLIR 如何执行你定义的 IR 转换逻辑    |
| 注册内容     | Dialect 的构造器函数（工厂方法） | Pass 的创建函数（lambda 返回 unique_ptr） |
| 注册对象     | DialectRegistry                  | `mlir::registerPass()`                    |
| 是否立即创建 | ❌否                              | ❌否                                       |
| 什么时候创建 | 解析 .mlir 文件时                | 运行 PassPipeline 时                      |
| 作用         | 识别和管理你的 Dialect 中的 Ops  | 做转换优化，比如 Top → Tpu                |
| 本质         | 储存构造器/函数指针以供后用      | 储存 Pass 工厂函数供 PassManager 使用     |





### 4、具体使用流程

假设你有一个 `.mlir` 文件如下：

```
module{
	func.func @main() -> tensor<1x1000xf32> {
		%0 = top.Conv(%arg0) : (tensor<1x3x224x224xf32>) ->tensor<1x1000xf32>
		func.return 0% "tensor<1x1000xf32>"
	}
}
```

运行的命令是：

```
tpuc-opt test.mlir --convert-top-to-tpu
```

我们已经注册过的内容有：

- 一个叫 `top` 的 Dialect（方言）；

- 一个叫 `convert-top-to-tpu` 的 Pass。



那么整个过程可以分为以下5步

**（1）程序启动**

`tpuc-opt.cpp` 里你写了：

```c++
tpu_mlir::registerAllPasses();
tpu_mlir::registerAllDialects(registry);

```

这时：

- 所有 Dialect 被注册到 `registry`（注册 = 把构造器登记进去）；
- 所有 Pass 被注册到全局 PassRegistry（也是登记构造方法）；

📌 这一步并没有构造对象，仅仅是登记：
 “以后如果用到 `top` 这个 Dialect，就用这个构造函数去创建它”。



**（2）解析IR文件时遇到Dialect**

```
tpuc-opt test.mlir
```

那么程序会调用

```c++
MlirOptMain(argc, argv, ..., registry)
```

这时开始解析test.mlir文件，第一行卸责：

```
top.Conv(...)
```

于是：

👉 MLIR 在 registry 中查找有没有注册过 `top` 这个 Dialect；

👉 找到了，于是调用你注册时登记的构造函数（例如 `Top::TopDialect::TopDialect(...)`）

👉 实际创建一个 `TopDialect` 实例出来！

✅ 此时 `Dialect` 被真正构造，用来帮助解析、打印、验证 IR 中的 `top.Conv` 这样的 op。

**（3）解析命令行参数，决定要跑哪个Pass**

你的命令里写了：

```
--convert-top-to-tpu
```

 MLIR 会查找是否有叫 `convert-top-to-tpu` 的 Pass 被注册过？

查找时发现你注册过：

```
mlir::registerPass([]() {
  return std::make_unique<ConvertTopToTpuPass>();
});
```

于是调用这个 lambda，创建一个 Pass 实例：

```c++
std::unique_ptr<Pass> p = createConvertTopToTpu();
```

这个 Pass 实例被放入 `PassManager` 里，准备执行。



**（4）执行Pass的runOnOperation**

```
ConvertTopToTpuPass::runOnOperation()
```

这时你的 Pass 就开始工作了，它会：

1. 遍历 Module 或 Func 里的 IR；
2. 找到 `top.Conv` 这样的 op；
3. 替换成 `tpu.Conv` 或其他目标 op；

✅ 到这里，你的 IR 经过 Pass 变成了新的形式。



**（5）输出结果**

`tpuc-opt` 根据命令行输出参数，将优化后的 IR 写出：

```
-o out.mlir
```

### 3、为什么函数可以作为参数直接传递？
