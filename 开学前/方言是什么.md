#### 1、Dialect

在MLIR中Dialect是一套属于某个领域的**语言**，所以叫方言

**Dialect = 某个领域内定义的一组操作（Ops）+ 类型（Types）+ 属性（Attrs）**

**举例：下面有很多dialect，他们中有类似的操作，但是互相之间不能理解，所以叫做方言**

| Dialect 名字 | 所属领域          | 示例操作                                |
| ------------ | ----------------- | --------------------------------------- |
| `arith`      | 基本算术          | `arith.addf`（浮点加法）                |
| `tensor`     | 张量操作          | `tensor.extract`、`tensor.insert`       |
| `linalg`     | 线性代数          | `linalg.matmul`, `linalg.conv`          |
| `tosa`       | 通用神经网络推理  | `tosa.add`, `tosa.relu`                 |
| `onnx`       | ONNX 模型语义     | `onnx.MatMul`, `onnx.Gemm`, `onnx.Relu` |
| `llvm`       | 低级汇编/代码生成 | `llvm.store`, `llvm.call`               |

**MLIR的本质就是方言之间的转换吗？**

是的，MLIR本质就是围绕不同的Dialect进行优化和转换以此来组织整个AI编译器流程



**什么是 MLIR Pass + Lowering？**

将高层次语义逐步转换成低层次语义，直到变成机器能理解和执行的代码，这就是一个不断lowering的过程，在MLIR中这个过程是通过多个Pass实现的。

**举例**

```
ONNX Dialect（高层模型表达）
   ↓ Pass 1：ONNX Lower 到 TOSA 或 Linalg
TOSA / Linalg Dialect（中间张量级表示）
   ↓ Pass 2：转换为 memref（内存表示） + 控制流
memref / affine / scf Dialect
   ↓ Pass 3：转为 LLVM IR Dialect
LLVM Dialect（低层次汇编语义）
   ↓ LLVM 编译器后端
目标平台的汇编或机器码（x86 / ARM / TPU）
```

每一步的“Pass”负责某种语义或结构的转换，比如：

- ONNX → TOSA：将高层神经网络操作变为通用深度学习算子
- TOSA → memref：将张量计算变成内存索引操作
- memref → LLVM：变成 LLVM 级别的 load/store/intrinsics



**因此Dialect就有多个等级之分，从高级一直到低级，实际上这就是LLVM一直以来的演化过程**

| 层次               | 类比于编程语言        | 示例                         |
| ------------------ | --------------------- | ---------------------------- |
| High-Level Dialect | 类似 Python / PyTorch | `onnx.MatMul`, `onnx.Relu`   |
| Mid-Level Dialect  | 类似 C                | `linalg.matmul`, `tosa.relu` |
| Low-Level Dialect  | 类似汇编语言          | `llvm.load`, `llvm.call`     |



**Dialect是不是可以直接调用？**

在 MLIR 中，每一个 Dialect 必须先被 **注册进编译器框架中（比如 mlir-opt 工具）**，然后才能调用。

```
module {
  func.func @main(%a: memref<4x4xf32>, %b: memref<4x4xf32>) -> memref<4x4xf32> {
    %c = linalg.matmul ins(%a, %b : memref<4x4xf32>, memref<4x4xf32>) -> memref<4x4xf32>
    return %c : memref<4x4xf32>
  }
}
```

上面的这段MLIR代码用了linalg.matmul，也就是用了linalg这个方言，因此前提就是在 MLIR 编译工具中加载了 `linalg` Dialect，Dialect 实际上就是 C++ 中的类，通过 C++ 插件机制注册进来。



**MLIR文件是怎样运行的？**

MLIR文件本身不能直接运行，主要就是作为IR中间表示来看的，在不同的dialect下进行一定的优化



**dialect都是MLIR自带的吗？**

不是

| Dialect                                                      | 来源                                      |
| ------------------------------------------------------------ | ----------------------------------------- |
| `std`, `func`, `tensor`, `arith`, `memref`, `scf`, `cf`, `llvm` | **MLIR 官方内置**                         |
| `linalg`, `tosa`, `affine`                                   | **MLIR 附带扩展**                         |
| `onnx`                                                       | **第三方 MLIR 项目：onnx-mlir**           |
| 自定义 Dialect                                               | **你可以自己定义**，比如 llama2_dialect！ |





**实际案例：ONNX → TOSA → LLVM 的 Lowering 示例**

1：ONNX Dialect   这里直接从ONNX文件转为MLIR文件就是这种格式

```
module {
  func.func @main(%a: tensor<4xf32>, %b: tensor<4xf32>) -> tensor<4xf32> {
    %res = "onnx.Add"(%a, %b) : (tensor<4xf32>, tensor<4xf32>) -> tensor<4xf32>
    return %res : tensor<4xf32>
  }
}
```

2：Lower 到 TOSA Dialect

使用 `mlir-opt` 进行 lowering（在终端里跑）：

```
mlir-opt input.mlir -convert-onnx-to-tosa > tosa.mlir
```

产出类似于

```
module {
  func.func @main(%a: tensor<4xf32>, %b: tensor<4xf32>) -> tensor<4xf32> {
    %res = "tosa.add"(%a, %b) {quantization_info = none} : (tensor<4xf32>, tensor<4xf32>) -> tensor<4xf32>
    return %res : tensor<4xf32>
  }
}
```



3: Lower 到 LLVM Dialect

继续运行：

```
mlir-opt tosa.mlir -tosa-to-linalg -convert-linalg-to-loops -lower-affine -convert-scf-to-cf -convert-memref-to-llvm -convert-func-to-llvm -reconcile-unrealized-casts > llvm.mlir
```

生成类似：

```
module {
  llvm.func @main(%arg0: !llvm.ptr<f32>, %arg1: !llvm.ptr<f32>) -> !llvm.ptr<f32> {
    ; LLVM 指令表示
  }
}
```
