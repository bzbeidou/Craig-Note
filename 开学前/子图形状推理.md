#### 2、模型太大，onnx.shape_inference.infer_shapes()无法直接处理

**解决方法**  ：三个方法  第一种相对好用

**一：只对子图做shape推理**

你不需要对整个 13GB 的 LLaMA2 模型做推理。**可以先提取一个子图（比如某一层的 attention 子图），然后对这个小模型调用 `infer_shapes()`。**

常用工具：

`onnx.utils.extract_model`：用于提取模型的部分节点。

只需要提供起始和种植tensor的名字（比如 `input_412` 到 `output_512`），写代码提取子图并做 shape 推理。

**二：自己构建 shape 映射（不依赖 `infer_shapes`）**

**三：用 `onnxruntime` 运行部分推理取 shape**



整体思路：获取子图小模型，再做形状推理得到算子



#### 3、拆分onnx格式的模型

  onnx格式保存的的是纯粹的算子图，不像PyTorch这样由清晰的模块/类/层的定义

**通常包含的模块,结构很不清晰，全是算子，只能自己推**

1. **Token Embedding 层**
2. **位置编码（RoPE）**
3. **多个重复的 Transformer Block（含自注意力 + FFN）**
4. **最终 LayerNorm + 输出投影（lm_head）**

**重点：TransformerBlock结构拆解**

```
输入 →
  LayerNorm →
    (Q, K, V 投影 → RoPE → Attention) →
  Add残差 →
  LayerNorm →
    前馈网络 (FFN) →
  Add残差 →
输出

```

*这里有一个问题是在我的onnx模型中并没有ffn类似的名字，只有post_attetnion_layer_norm*

**(1)词嵌入层（token_embedding）**

```
输入: input_ids (shape: [batch, seq_len])
算子: Gather → Shape → Expand → ...
作用: input_ids → one-hot 编码 → 映射到词向量

```

通常看见 `Gather`, `Shape`, `Expand` 这些就是嵌入相关,LLaMA2 没有 PositionEmbedding，而是 RoPE

**(2)RoPE（旋转位置编码）**

```
输入: Q, K 向量
算子: Reshape → Transpose → Slice → Concat → Cos/Sin → Mul → Add
作用: 应用旋转位置编码
```

会看到一个复杂结构，将 Q/K 做旋转处理（RoPE 的 apply_rotary_emb 部分），这个图一般比较难看，但只要看到 Transpose + Sin/Cos + Mul + Add，很可能就是 RoPE。

**(3) Self-Attention 模块**

```
输入: hidden_states
算子组合（按顺序）：

  Linear(QKV): MatMul + Add → Q, K, V 三路
  →
  RoPE 编码（前面提到）
  →
  Attention：
    Q @ K.T → MatMul
    →
    attention_mask（广播）→ Add
    →
    Softmax → Dropout
    →
    MatMul(QK, V) → Attention输出

```

这些都是常见算子

**(4)前馈网络FFN**

```
输入: Attention输出
算子组合：
  Linear1: MatMul + Add →
  Activation: GELU or SiLU (LLaMA2 是 SiLU，一般是 Mul + Sigmoid) →
  Linear2: MatMul + Add

```

**(5)残差连接**

```
Add (原始输入 + 子层输出)
```

算子简单但是位置关键

**（6）输出层**

```
最后的 LayerNorm →
MatMul（投影回 vocab_size）

```

**总结：如何在netron中识别出结构块**

用权重名比如layers.0.attention

没有权重名则使用上面说的一些组合方式来区分



#### 4、获得子图后可以进行推理

**注意：**

**（1）必须提供实际输入数据**

**例如：**

```
/model/model/embed_tokens/Gather_output_0
/model/model/rotary_emb/Cast_4_output_0
/model/model/rotary_emb/Cast_5_output_0
/model/model/Mul_6_output_0

```

必须准备这些张量的 NumPy 数据，**形状、数据类型必须匹配**，否则会报错。

**(2)如何推理子图？**

```
import onnxruntime as ort
import numpy as np

# 加载 ONNX 模型
session = ort.InferenceSession("your_subgraph.onnx", providers=["CPUExecutionProvider"])

# 准备输入数据（你要确保 shape 和 dtype 与模型一致）
inputs = {
    "/model/model/embed_tokens/Gather_output_0": np.random.randn(1, 128, 4096).astype(np.float32),
    "/model/model/rotary_emb/Cast_4_output_0": np.random.randn(1, 128, 64).astype(np.float32),
    "/model/model/rotary_emb/Cast_5_output_0": np.random.randn(1, 128, 64).astype(np.float32),
    "/model/model/Mul_6_output_0": np.random.randn(1, 1, 128, 128).astype(np.float32),
}

# 推理
outputs = session.run(None, inputs)

# 输出结果
for i, output in enumerate(outputs):
    print(f"输出 {i} 形状：", output.shape)

```

**(3)因此要有输入就必须推上一层**

也就是链式调用，从上往下



#### 5、如何获得每一层的算子结构？ ----两步

**（1）设置中间输出算子的输出为输出，然后导出为新模型**

**（2）对新模型进行推理**

在 ONNX 模型中，有些节点可能只有输入和中间的计算过程，未显示输出。我们通过将这些中间输出（`graph.value_info`）动态添加到模型的输出列表中，确保我们能获得模型计算过程中每个节点的输出信息，这样相当于得到一个新模型，里面有很多输出。

对新模型执行推理就可以得到构造好的算子数据。
