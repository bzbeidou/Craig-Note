1、pattern复习

```c++
class ConvertAddOpPattern : public OpRewritePattern<top::AddOp>
```

这是一个专门匹配 `top::AddOp` 的 Pattern

其中有一个关键函数需要具体实现,这个函数就是在遇到`top::AddOp`的时候调用的函数，然后把它变成`tpu::AddOp`

```c++
LogicalResult matchAndRewrite(top::AddOp op, PatternRewriter &rewriter) const override;
```

- 首先类似上面的类对于其他的Op都要定义单独的pattern类，相当于每个Pattern负责一个类型的Op转换，然后需要调用自带的pattern.add函数将这些类给放到ctx这个上下文环境里

```c++
patterns.add<ConvertAddOpPattern>(ctx);
patterns.add<ConvertConvOpPattern>(ctx);
```

- 然后在Pass中调用MLIR的工具函数（这一步到了Pass里面，也就是在Pass里去用pattern）

```c++
applyPatternsAndFoldGreedily(module, std::move(patterns));
```

这个函数内部就是遍历module，如果碰到了某个Op能和某个Pattern匹配上，就对他应用pattern的那个方法（所以叫做匹配重写  即Rewrite Pattern）

- **不写的时候，在Pass内直接遍历当于也是写pattern

```c++
for (auto func : module.getOps<FuncOp>()) {
  for (auto op : func.getOps<top::AddOp>()) {
    // 手动构造 tpu::AddOp，替换 op
  }
}
```

- **写了pattern，不仅清晰（将pattern单独作为了一个类**

```c++
class ConvertAddOpPattern : public OpRewritePattern<top::AddOp> {
  LogicalResult matchAndRewrite(top::AddOp op, PatternRewriter &rewriter) const override {
    rewriter.replaceOpWithNewOp<tpu::AddOp>(op, ...);
    return success();
  }
};

```

```c++
patterns.add<ConvertAddOpPattern>(ctx);
applyPatternsAndFoldGreedily(...);
```

2、复习写一个Pass

编写一个Pass：把所有的 `top::AddOp` 替换成 `tpu::AddOp`

**很基础**

- 新建项目目录

```
TopToTpu/
├── CMakeLists.txt
├── TopToTpuPass.cpp      ← 会把代码写在这里
└── TopToTpu.h            ← 声明 Pass 类
```

- **（1）声明Pass类**

```c++
#pragma once
#include "mlir/Pass/Pass.h"
#include "tpu_mlir/Dialect/Top/IR/TopOps.h"
#include "tpu_mlir/Dialect/Tpu/IR"

namespace tpu_mlir{
	struct SimpleTopToTpuPass : public mlir::PassWrapper<SimpleTopToTpuPass, mlir::OperationPass<mlir::ModuleOp>>{
        void runOnOperation() override;
    };
    
    std::unique_ptr<mlir::Pass> createSimpleTopToTpuPass();
}
```

- **（2）实现Pass（TopToTpuPass.cpp）**

```c++
#include "TopToTpu.h"
#include "mlir/IR/PatternMatch.h"
#include "mlir/Transforms/DialectConversion.h"

using namespace mlir;

namespace tpu_mlir {


class ConvertAddOpPattern : public OpRewritePattern<top::AddOp> {
public:
  using OpRewritePattern::OpRewritePattern;

  LogicalResult matchAndRewrite(top::AddOp op, PatternRewriter &rewriter) const override {
    // 获取输入与输出
    auto inputs = op->getOperands();
    auto output_type = op->getResult().getType();

    rewriter.replaceOpWithNewOp<tpu::AddOp>(op, output_type, inputs);

    return success();
  }
};

void SimpleTopToTpuPass::runOnOperation() {
  MLIRContext *ctx = &getContext();
  ModuleOp module = getOperation();

  RewritePatternSet patterns(ctx);
  patterns.add<ConvertAddOpPattern>(ctx);

  if (failed(applyPatternsAndFoldGreedily(module, std::move(patterns)))) {
    module.emitError("Failed to apply TopToTpu rewrite patterns");
    signalPassFailure();
  }
}
std::unique_ptr<Pass> createSimpleTopToTpuPass() {
  return std::make_unique<SimpleTopToTpuPass>();
}

} // namespace tpu_mlir

```

- **（3）注册Pass**

```c++
#include "tpu_mlir/Conversion/TopToTpu/TopToTpu.h"

namespace {
  struct Register {
    Register() {
      mlir::PassRegistration<tpu_mlir::SimpleTopToTpuPass>(
        "simple-top-to-tpu", 
        "Convert top::AddOp to tpu::AddOp");
    }
  } registerPass;
}

```

 **这里有一个问题是为什么不用registerPass这个函数，**

| 步骤                                  | 说明                                         |
| ------------------------------------- | -------------------------------------------- |
| 定义一个 `Register` 结构体            | 它的构造函数里写注册逻辑                     |
| 定义一个 `registerPass` 静态变量      | 一旦程序运行，就自动执行构造函数             |
| 构造函数中调用 `PassRegistration<>()` | 把 Pass 名称和工厂函数注册到系统中           |
| 你不用写任何调用代码                  | 只需要链接这个 `.cpp` 文件，注册就会自动发生 |

优点就是无调用代码，链接之后就会自动注册，但是不建议用这种，太抽象了，可以先了解即可

**（1）先编写注册函数**

```c++
void registerSimpleTopToTpuPass() {
  mlir::PassRegistration<tpu_mlir::SimpleTopToTpuPass>(
    "simple-top-to-tpu",
    "Convert top::AddOp to tpu::AddOp");
}
```

**（2）在主程序中手动调用它（比如在tpuc-opt.cpp）**

```c++
int main(int argc, char **argv) {
  registerSimpleTopToTpuPass(); //  手动注册
  return mlir::MlirOptMain(...);
}
```

**mlir::registerPass()是我们之前用的，他也是显式注册，但是是匿名Pass，比如上面的Pass我们有说明是命令simple-top-to-tpu，但是如果mlir::registerPass()这个则不能设置**,是这样用的

```c++
mlir::registerPass([]() -> std::unique_ptr<Pass> {
  return std::make_unique<MyPass>();
});

```

**（4）CMakeLists.txt 中添加 Pass 文件**

```c++
add_mlir_library(TopToTpu
  TopToTpuPass.cpp

  LINK_LIBS PUBLIC
  MLIRIR
  MLIRPass
  TPUMLIRTopDialect
  TPUMLIRTpuDialect
)

```

- **（5）运行这个Pass**

如果你编译好了 `tpuc-opt` 或其他工具，可以用如下命令：

```
tpuc-opt your_model.mlir -simple-top-to-tpu
```

它会自动运行这个 Pass，把所有的 `top.AddOp` 替换为 `tpu.AddOp`。

3、 对比显式注册的两种方式

（1）`mlir::registerPass(...)` ：

```c++
mlir::registerPass([]() -> std::unique_ptr<Pass> {
  return std::make_unique<MyPass>();
});
```

写了一个自定义的 Pass，但不打算通过命令行选项 `-xxx` 去调用它

（2） `mlir::PassRegistration<T>` 

```c++
mlir::PassRegistration<MyPass>("my-pass", "some description");
```

这是最标准、最完整的注册方式会自动给你绑定命令行选项名 `-my-pass`

- `mlir::PassRegistration<T>` 的构造函数里会调用一个底层工具函数，最终会向 `PassRegistry::get()` 注册一条信息
- `mlir::registerPass()` 也是调用 `PassRegistry::get().registerPass(...)`，只是方式不同

4、PassManager是什么

**顾名思义，是用来管理所有Pass的，每个Pass都是一个类，用到的时候就是一个实例，PassManager也是一个类，用到的时候需要实例化如下手动构造**



**在MLIR中PassManager是什么样？**

- 实例代码（手动构造PassManager）

```c++
mlir::MLIRContext context;
mlir::OwningOpRef<mlir::ModuleOp> module = parseSourceFile(..., &context);

// 手动构造 PassManager
mlir::PassManager pm(&context);

// 加入一个 Module 级别的 Pass
pm.addPass(mlir::createCanonicalizerPass());

// 加入一个 Function 级别的 Pass（会自动进入函数内部运行）
pm.addNestedPass<mlir::FuncOp>(mlir::createCSEPass());  // common subexpression elimination

// 运行所有 Pass
if (mlir::failed(pm.run(*module))) {
  llvm::errs() << "Passes failed.\n";
  return 1;
}

```



**1、`addPass(std::unique_ptr<Pass>)`**

添加一个作用在顶层 Operation（如 ModuleOp）上的 Pass。

```c++
PassManager pm(&context);
pm.addPass(createCanonicalizerPass());

```

表示加一个**顶层 Canonicalizer Pass**，会运行在 `ModuleOp` 上

**这里回顾一下ModuleOp、FuncOp等等**



**2、 `addNestedPass<OpT>(std::unique_ptr<Pass>)`**

加一个作用在子级 Op 上的 Pass，比如 `FuncOp`、`BlockOp` 等。

```c++
pm.addNestedPass<FuncOp>(createCSEPass());
```

表示：对模块中的每一个 `FuncOp`，都运行一次 `CSEPass`

**3、`nest<OpT>()`**

在某个子 Op（如 FuncOp）层级创建一个子 PassManager，后续可以向这个子级添加多个 Pass。

```c++
auto &funcPM = pm.nest<FuncOp>();
funcPM.addPass(createCSEPass());
funcPM.addPass(createSymbolDCEPass());
```

表示：对每个 `FuncOp`，都执行两个 Pass：`CSE` → `Symbol Dead Code Elimination`

**4、 `run(Operation &op)`**

运行 `PassManager` 里添加的所有 Pass，在指定的 IR 上执行。

```c++
mlir::ModuleOp module = ...;
if (failed(pm.run(module))) {
  llvm::errs() << "Pass execution failed\n";
}

```

最关键的一步，没有 `run()`，一切 Pass 都只是摆设。

```
PassManager
│
├─ addPass()              ← 加模块级别的 Pass
├─ addNestedPass<FuncOp>  ← 加函数级别的 Pass
├─ nest<FuncOp>()         ← 创建子 PassManager 专管 FuncOp
│   ├─ addPass()          ← 给 FuncOp 加多个 Pass
│   └─ ...
│
├─ enableIRPrinting()     ← 打印每步 IR，调试超好用
├─ enableVerifier()       ← 自动加合法性检查
├─ run(module)            ← 执行所有 Pass，必需
└─ getOpName()            ← 查看当前作用对象类型

```

5、MLIR中的操作类型  也就是Op类型  所以MLIR中的Op是有不同的类型的

```
mlir::ModuleOp  ← 顶层 Module
│
├── mlir::FuncOp  ← 一个函数
│   ├── Operation ← 一条计算操作（如 add、mul、relu）
│   └── ...
│
├── mlir::GlobalOp / TensorOp / CustomOp
│   └── ...
│
└── ...
```



在mlir文件中，所有的内容都是Op操作，但是Op也有类型之分，比如顶层的ModuleOp，其下的FuncOp，以及最基本的Operation，一共就这几种



在c++代码里，每个Op实际上都是一个类，比如ModuleOp类，FuncOp类等等，所以无论是ModuleOp还是其他都是一个类，但是在.mlir文件里要区分一下操作类型，就是Op类型

**实例IR**

```
module {
  func.func @add_one(%arg0: i32) -> i32 {
    %0 = arith.addi %arg0, %c1 : i32
    return %0 : i32
  }
}
```

这段代码等价于：

- `module` → `ModuleOp`
- `func.func` → `FuncOp`
- `arith.addi` → 一个 Op，`AddIOp`
- `return` → 一个 ReturnOp





但是为什么要区分这些呢，他们都是Op，而且底层都是类，为什么要区分呢？实际上就是为了Pass指定跑在不同的Op上

因为 **不同的优化 Pass 是针对不同层级设计的**，你不能混着来：



| Pass 类型                 | 运行在哪个 Op 上 | 作用范围                     |
| ------------------------- | ---------------- | ---------------------------- |
| `OperationPass<ModuleOp>` | 模块层级         | 可以遍历函数、全局变量、配置 |
| `OperationPass<FuncOp>`   | 函数层级         | 优化函数体内部的算子         |
| `OpRewritePattern<AddOp>` | 某个具体 Op      | 只重写特定类型的 Op          |



**回顾Pass定义时的写法：**

```
struct MyPass : public PassWrapper<MyPass, OperationPass<mlir::FuncOp>> {
  void runOnOperation() override {
    auto func = getOperation(); // 这里返回的就是一个 FuncOp
  }
};
```

如果你写的是 `OperationPass<ModuleOp>`，那 `getOperation()` 返回的就是一个 `ModuleOp`



**对照表：**

| 你看到的东西        | 代表的 MLIR 类型 | 在 C++ 中是            |
| ------------------- | ---------------- | ---------------------- |
| `module {}`         | `ModuleOp`       | `mlir::ModuleOp`       |
| `func.func @name()` | `FuncOp`         | `mlir::FuncOp`         |
| `arith.addi`        | `AddIOp`         | `mlir::arith::AddIOp`  |
| `return`            | `ReturnOp`       | `mlir::func::ReturnOp` |



**具体Pass针对不同的层级作用举例：**

用两个 Pass：

1. **Module 级 Pass**：统计模块中总共有多少个函数（`FuncOp`）。
2. **Function 级 Pass**：统计每个函数中有多少个操作（`Operation`）。

```mlir
module {
  func.func @add_one(%arg0: i32) -> i32 {
    %0 = arith.addi %arg0, %c1 : i32
    return %0 : i32
  }

  func.func @multiply_two(%arg0: i32) -> i32 {
    %0 = arith.muli %arg0, %c2 : i32
    return %0 : i32
  }
}
```

你看到有两个函数：`add_one` 和 `multiply_two`

每个函数中都有两个 Operation（`addi` 和 `return`）

- 第一种 Pass：ModuleOp 上运行

```c++
struct CountFuncPass : public PassWrapper<CountFuncPass, OperationPass<ModuleOp>> {
  void runOnOperation() override {
    ModuleOp module = getOperation();
    int count = 0;
    for (auto func : module.getOps<FuncOp>()) {
      count++;
    }
    llvm::outs() << "[ModuleOp] This module contains " << count << " functions.\n";
  }
};

```

功能：运行一次，**遍历整个 Module 中的 FuncOp**



- 第二种 Pass：FuncOp 上运行

```c++
struct CountOpInFuncPass : public PassWrapper<CountOpInFuncPass, OperationPass<FuncOp>> {
  void runOnOperation() override {
    FuncOp func = getOperation();
    int count = 0;
    for (auto &block : func) {
      for (auto &op : block) {
        count++;
      }
    }
    llvm::outs() << "[FuncOp] Function " << func.getName() << " has "
                 << count << " operations.\n";
  }
};

```

对每个函数都运行一次，**统计内部有多少行 IR（Op）**



- 注册并运行

```c++
mlir::PassManager pm(&context);
pm.addPass(std::make_unique<CountFuncPass>());
pm.addNestedPass<FuncOp>(std::make_unique<CountOpInFuncPass>());
pm.run(module);
```



输出效果

```
[ModuleOp] This module contains 2 functions.
[FuncOp] Function add_one has 2 operations.
[FuncOp] Function multiply_two has 2 operations.
```



**最重要的一点，通过getOperation（）函数实际上返回的就是当前这个Op的实例对象，`FuncOp func = getOperation();`,比如这个就是返回的一个FuncOp的实例对象func**



**因为继承PassWrapper的时候泛型里输入了一个FuncOp，那么此时父类的getOperation()函数就会在被调用时创建对应的Op类的实例对象**
