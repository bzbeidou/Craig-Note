#### 1、构建系统  Make和Ninja

CMake 和构建系统（make / ninja）之间非常核心的几个概念

**如何指定**

```
cmake .. //会默认指定一种构建方式
cmake -G "Unix Makefiles" .. //使用make作为后面的构造器
cmake -G "Ninja" .. //使用Ninja作为后面的构造器
```

G就是Generator 指选择构造器

**两种不同的命令cmake之后生成的文件有什么不同**

`make` 构建生成的中间文件：

- 生成的文件：`Makefile`、`CMakeCache.txt`、以及编译过程中生成的目标文件（例如 `.o` 文件）。
- 位置：`Makefile` 会生成在 `build/` 文件夹中，

`ninja` 构建生成的中间文件：

- 生成的文件：`build.ninja`、`CMakeCache.txt`、以及编译过程中的目标文件（如 `.o` 文件），但是这些文件的管理会依赖于 `ninja` 的规则。
- 位置：`build.ninja` 文件在 `build/` 文件夹中

**但是无论是make之后还是ninja之后生成的目标文件都是一样的**

*如果这次用了ninja，后面想用cmake那么就要删掉build重新cmake*

**流程小结：**

**CMake配置阶段**：

- CMake 会根据你选择的生成器（`make` 或 `ninja`）生成相应的构建系统文件（`Makefile` 或 `build.ninja`）。

**编译阶段**：

- **`make`**：根据 `Makefile` 文件来查找如何编译和链接目标。
- **`ninja`**：根据 `build.ninja` 文件来管理依赖关系和编译任务。

编译过程中，会生成 `.o` 或其他中间文件，最后这些文件会被链接器（`ld` 或 `clang++`）合并成最终的可执行文件或库。

**（2）简化版llvm内的ArrayRef**

```c++
#include <iostream>
#include <vector>
#include <cassert>

// 模板类定义：泛型支持任意类型 T
template <typename T>
class MyArrayRef {
public:
    // 构造函数：从指针和长度构造
    MyArrayRef(const T *data, size_t length)
        : dataPtr(data), length(length) {}

    // 从 std::vector 构造
    MyArrayRef(const std::vector<T> &vec)
        : dataPtr(vec.data()), length(vec.size()) {}

    // 元素个数
    size_t size() const { return length; }

    // 是否为空
    bool empty() const { return length == 0; }

    // 元素访问：只读
    const T &operator[](size_t index) const {
        assert(index < length && "Index out of bounds!");
        return dataPtr[index];
    }

    // 获取底层数据指针
    const T *data() const { return dataPtr; }

private:
    const T *dataPtr; // 指向原始数据的指针
    size_t length;    // 长度
};

```





**详解两种构造函数**

```c++
    // 构造函数：从指针和长度构造
    MyArrayRef(const T *data, size_t length)
        : dataPtr(data), length(length) {}

    // 从 std::vector 构造,这里还涉及了一个java和c++的区别
    MyArrayRef(const std::vector<T> &vec)
        : dataPtr(vec.data()), length(vec.size()) {}
```

**第一个构造函数是给数组/指针这类“纯数据”的结构用的**

这些东西就是一段连续的原始数据，没有行为（函数），只有值。

```c++
int arr[] = {10, 20, 30};
MyArrayRef<int> a(arr, 3);  // 直接引用一段原始数据
```

**第二个构造函数则是给c++对象（比如std::vector）这种有行为的类型用的**

```
std::vector<int> v = {1, 2, 3, 4};
MyArrayRef<int> b(v);  // 内部通过 vec.data() 获取地址
```

*实际例子*

```c++
int arr[] = {10, 20, 30};

std::vector<int> v = {1, 2, 3, 4};
// 用指针 + 长度构造（传地址）
MyArrayRef<int> a(arr, 3);


// 用 vector 构造（传引用）
MyArrayRef<int> b(v);
```

**（5）运算符重载operator overloading   巨抽象**

```c++
const T &operator[](size_t index) const
```

**operator[]是c++规定的一个特殊函数名, 用于让对象能使用中括号运算符**

**前面的&是返回类型的一部分，表示返回类型是T &,也就是一个引用T类型，而且是返回常量引用**

*所以运算符重载到底是什么？*

c++允许运算符的重载，比如下面的代码

```c++
Vector2D a(1, 2);
Vector2D b(3, 4);
Vector2D c = a + b;  // ✅ 实际调用了：a.operator+(b)

//这里是提前定义了Vector2D这个类，然后创建了a和b两个对象
```

**问题：a和b两个对象怎么能用 `a+b`这样呢，怎么实现的加法？**

**这就是运算符的重载，实际上是调用了a对象里的函数operator+**

```c++
a.operator+(b);//实际上是这个，这就是重载了运算符+
```

**完整代码如下：**

```c++
class Vector2D {
public:
    int x, y;

    Vector2D(int x, int y) : x(x), y(y) {}
    // 这是运算符重载：让+支持两个 Vector2D 相加
    Vector2D operator+(const Vector2D& other) const {
        return Vector2D(x + other.x, y + other.y);
    }
};


//很明显使用a+b的时候就调用了这个operator+函数，然后b则是作为参数传入的，这就是重载
```

**常用的运算符重载还有很多，如下**

| 运算符 | 重载函数名   | 示例                |
| ------ | ------------ | ------------------- |
| `+`    | `operator+`  | `a + b`             |
| `-`    | `operator-`  | `a - b`             |
| `*`    | `operator*`  | `a * b`             |
| `/`    | `operator/`  | `a / b`             |
| `==`   | `operator==` | `a == b`            |
| `[]`   | `operator[]` | `a[i]`              |
| `()`   | `operator()` | `a(10)` —— 函数对象 |
| `<<`   | `operator<<` | `std::cout << obj`  |
| `>>`   | `operator>>` | `std::cin >> obj`   |

**一句话，运算符重载就可以让对象使用普通运算符**

```c++
}
```


**静态函数的部分**

```c++
static MyTypeStorage *construct(mlir::TypeStorageAllocator &allocator, const KeyTy &key)

```

| 部分                                                        | 解释                                                         |
| ----------------------------------------------------------- | ------------------------------------------------------------ |
| `static`                                                    | 表示这是一个“静态函数”，不依赖任何具体对象。即：不需要创建对象也能调用 |
| `MyTypeStorage *`                                           | 返回类型：是一个指向 `MyTypeStorage` 的 **指针**，而不是对象本体 |
| `construct`                                                 | 函数名，叫做 `construct`，你可以理解为“构造器”               |
| `(mlir::TypeStorageAllocator &allocator, const KeyTy &key)` | 函数的参数：一个分配器（引用），一个类型的“Key”              |

**这里有个问题就是返回的是指针类型，而不是一个对象，是因为new的肯定在堆里，那么返回的就是指针，与前面c++的部分有区别**

| 写法                            | 含义         | 内存位置 | 说明                                 |
| ------------------------------- | ------------ | -------- | ------------------------------------ |
| `MyClass obj;`                  | 栈上创建对象 | 栈       | 直接存放对象本体                     |
| `MyClass *ptr = new MyClass();` | 堆上创建对象 | 堆 + 栈  | 对象在堆，`ptr` 存在栈上，是一个指针 |
| `MyClass &ref = obj;`           | 引用别名     | 同 obj   | `ref` 是 `obj` 的别名，不是指针      |

```c++
auto copiedShape = allocator.copyInto(std::get<0>(key));
```

从 `key` 中取出形状（shape）这个数组，**复制到 MLIR 内部托管的内存中**，并返回新的数组引用。
