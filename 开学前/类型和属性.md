#### 1、Type相关

**（1）生成的.h文件内容**

| 函数名                      | 作用            |
| --------------------------- | --------------- |
| `get(...)`                  | 构造 Type       |
| `getChecked(...)`           | 构造并验证 Type |
| `verify(...)`               | 检查参数合法性  |
| `verifyInvariants(...)`     | 可选的深度检查  |
| `parse(...)` / `print(...)` | 文本格式支持    |

**（2）TableGen的builders字段**

builders是一个数组，用来告诉TableGen生成什么样的构造函数

**语法结构详解**

```
let builders = [
  TypeBuilder<(ins ParamType1:$name1, ParamType2:$name2), [{
    // 构造逻辑（返回类型）
    return $_get(...);
  }]>
];

```

*首先builders本身是一个数组，里面每个元素都是一个builder描述，对应着生成的构造函数（一般是静态工厂模式）*

```
TypeBuilder<(参数列表), [构造函数体]>
```

*这段代码则对应着生成的构造方法，如下*

```c++
static NSTensorType get(...)
```



**参数列表部分**

ins代表后面的是生成的构造方法内的参数，比如这里就是对应生成的方法有两个参数

```
static NSTensorType get(::mlir::ArrayRef<int64_t> shape,
                        ::mlir::Type elementType);

```

**构造函数体部分**

```
return $_get(elementType.getContext(), shape, elementType, 0);
比如这样的构造函数体，这里的$_get(...)是一个tablegen的宏，会自动调用Base::get这个部分，先了解即可
```



**综上，builders内的一个builder及构建就讲完了**

一个builders内当然可以有多个builder，也就是对应生成多个builder函数

```
let builders = [
  TypeBuilder<(ins ArrayRef<int64_t>:$shape, Type:$elementType), [{
    return $_get(elementType.getContext(), shape, elementType, 0);
  }]>,
  TypeBuilder<(ins Type:$elementType), [{
    // 默认 shape 为空，device_id = -1
    return $_get(elementType.getContext(), {}, elementType, -1);
  }]>
];

//这里当然对应生成两个构造方法，参数数量不一样
```



**（3）生成的.c部分**

**类型解析器**generatedTypeParser

  读取到.mlir文件，识别类型字符串（如 `ns_tensor`），然后选择到对应的parser()函数，并调用其完成解析

  只需要知道这个函数是用来识别.mlir中类型的部分即可，这个是完全由tablegen生成的，但是parser是由我们自己写的

  .mlir文件经过处理之后生成的是c++实例对象，就是对象 直接在内存中，然后可以用c++代码调用

**类型打印器**generatedTypePrinter

  根据传入的Type对象的实际类型（例如NSTensorType），找到对应的print()方法输出IR文本，目前理解的是经过parser之后生成对象，然后可以通过这个generatedTypePrinter来调用print打印



**parser**

把文本内容解析为 C++ 的 Type 对象（如 `NSTensorType`），类似于从ast到mlir的过程，但是这里的parser是从mlir文本到ir对象的过程，因此最后肯定是构造并返回一个NSTensorType实例对象。

**print**

将当前对道德Type对象变成一段文本，可以写道mlir文件或者终端中



**（4）对.mlir文件的处理**

在学习mlir处理的时候，暂时不需要关心从ast到编译器的部分。

关心对.mlir文件的处理，一般是自己写一个mlir文件，然后对其进行处理，所以在定义dialect的时候关于Type的处理部分也要做好，也就是上面讲的



#### 2、Attribute    属性，就是编译期常量，用来表示操作的静态信息

对比C++语言来说，mlir中的Tpye是类型，难么Attribute就是指的常量，也就是属性，代表一个固定的值

**Attribute不是仅仅一个数值，固定的字符串这种也是Attribute**

分为枚举类Attribute和结构化Attribute，看下面详解



**视频记录**

定义attribute有两种，一种是根据枚举的attribute去生成，，另一种是通过mlir的attrdef去定义的

-----涉及到MLIR Attribute系统设计的两种建模方式

*都是tablegen得到的*

**（1）枚举类Attribute**

*如果信息来自一个固定剂和，那么可以用这个attr来表示，比如激活函数的类型`relu`,`tanh`*

*为什么不直接用字符串类型*

比如

```
%0 = mydialect.conv %x, %w attributes { activation = "relu" }
```

这里的“relu”就是字符串，但是这样是没有自动检查，可能拼错，因此MLIR提供了EnumAttr这个方法

**（2）结构化Attribute**

结构化Attr（AttrDef）是真正的Attribute类型，EnumAttr实际上是对字符串的封装

如果想表示多个字段的属性，比如张量的量化参数`scale=0.25, zero_point=128`，有多个字段的属性，所以停工了AttrDef





**（3）EnumAttr结构实战**

*第一步：定义枚举属性EnumAttr*

```
include "mlir/IR/OpBase.td"

def MyDialect : Dialect {
  let name = "mydialect";
  let cppNamespace = "mydialect";
}

// 枚举属性定义
def ActivationMode : StrEnumAttr<"ActivationMode", "Activation function mode"> {
  let cppNamespace = "::mydialect";
  let enumerants = [
    StrEnumAttrCase<"RELU", "relu">,
    StrEnumAttrCase<"TANH", "tanh">,
    StrEnumAttrCase<"NONE", "none">
  ];
}

//这里StrEnumAttr表示枚举值用字符串表示
//生成一个c++枚举 enum class ActivationMode

```

*第二步：定义使用该属性的Op*

```
def MyActivationOp : MyDialect_Op<"activation", [NoSideEffect]> {
  let summary = "Applies an activation function to the input";
  let description = [{
    This op applies a specified activation function to its input tensor.
  }];

  let arguments = (ins
    AnyType:$input,
    ActivationMode:$activation_mode
  );

  let results = (outs
    AnyType:$result
  );

  let assemblyFormat = [{
    $input attr-dict : type($input) -> type($result)
  }];
}

//这里ActivationMode:$activation_mode表示这个Op接受一个名为activation_mode地枚举类型
```

*第三步：生成c++代码*

Table会生成以下的部分

枚举类 `ActivationMode`

方法 `getActivationMode()` 返回枚举值

方法 `getActivationModeAttrName()` 返回属性名

方法 `parse`, `print`, `verify` 

只需要#include即可

```c++
#include "MyDialect/MyDialect.h"
#include "MyDialect/MyDialect.cpp.inc" // 自动生成的注册代码
#include "MyDialect/MyOps.cpp.inc"
#include "MyDialect/MyOpsEnums.cpp.inc" // ← 包含你的 enum 相关支持代码
```

*第四步：测试IR*

可以这样写MLIR文件

```
%0 = mydialect.activation %x {
  activation_mode = "relu"
} : tensor<4xf32> -> tensor<4xf32>
//如果把"relu"改成"relus"，那么MLIR会报错
```

*第五步：在c++ Pass中使用这个枚举*

```
if (auto actOp = dyn_cast<MyActivationOp>(op)) {
  switch (actOp.getActivationMode()) {
    case ActivationMode::RELU:
      llvm::outs() << "It's ReLU!\n";
      break;
    case ActivationMode::TANH:
      llvm::outs() << "It's tanh.\n";
      break;
    case ActivationMode::NONE:
      llvm::outs() << "No activation.\n";
      break;
  }
}
```



**4、AttrDef实战案例**

*第一 TableGen定义*

```
include "mlir/IR/AttrBase.td"

def MyDialect : Dialect {
  let name = "mydialect";
  let cppNamespace = "mydialect";
}

def QuantParamAttr : AttrDef<"QuantParam", MyDialect> {
  let parameters = (ins
    F32Attr:$scale,
    I32Attr:$zeroPoint
  );

  let assemblyFormat = "`<` $scale `,` $zeroPoint `>`";
}

// AttrDef<"QuantParam", MyDialect>表示这是一个输入MyDialect方言的Attribute，而且会对应生成一个名为QuantParam的c++类
//parameters则是定义的字段
//assemblyFormat代表在.mlir文件中这个Attribute长什么样，比如mydialcet.quant_param<0.25,128>
```

*第二 TableGen定义使用这个属性的Op*

```c++
def MyQuantizeOp : MyDialect_Op<"quantize", [NoSideEffect]> {
  let arguments = (ins
    AnyType:$input,
    QuantParamAttr:$qparam
  );
  let results = (outs AnyType:$output);

  let assemblyFormat = [{
    $input `qparam` `=` $qparam attr-dict : type($input) -> type($output)
  }];
}
```
