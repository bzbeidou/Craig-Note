| 继承方式         | 基类的 `public` 成员在子类中 | 基类的 `protected` 成员在子类中 | 用于什么场景                           |
| ---------------- | ---------------------------- | ------------------------------- | -------------------------------------- |
| `public` 继承    | 仍然是 `public`              | 仍然是 `protected`              | “is-a” 关系，如 `Student is a Person`  |
| `protected` 继承 | 变成 `protected`             | 仍然是 `protected`              | 较少见，适用于需要对子类部分隐藏的情况 |
| `private` 继承   | 变成 `private`               | 变成 `private`                  | 实现细节隐藏，不暴露接口               |

```c++
class Base {
public:
    void hello() {}
};

class Derived1 : public Base {};
class Derived2 : private Base {};

void test() {
    Derived1 d1;
    d1.hello();     // OK：public继承，Base::hello 是 public

    Derived2 d2;
    d2.hello();     // ❌ 错误：private继承，Base::hello 被变成 private
}

```

**java中并没有选择继承方式这一说法，继承就是把父类的成员一模一样的继承，除了private的成员**

**explicit   明确，  用在构造函数， 防止隐式转换，不重要**

```c++
class MyClass {
public:
    MyClass(int x) {}  // 没有 explicit
};

void test() {
    MyClass a = 5;  // ✅ 合法！5 被隐式转换,相当于MyClass(5)
}

//有时这种自动转换不安全，所以提供了explicit关键字，只能用MyClass(5)这样子

public:
    explicit MyClass(int x) {}
};

void test() {
    MyClass a = 5;      // ❌ 编译错误！explicit 禁止了隐式转换
    MyClass b(5);       // ✅ 明确调用是允许的
}


```

**（5）target_link_libraries命令**

就是link主程序和其他.cpp内文件定义的类、函数等，举例

我们目前已经写了一个MLIR Dialect，叫做`NorthStarDialect`，然后写了一个主程序来测试它，目前这个Dialect里只有能打印的功能

```c++
// main.cpp
#include "mlir/IR/Dialect.h"
#include "mlir/IR/MLIRContext.h"
#include "Dialect/NorthStar/IR/NorthStarDialect.h"

int main() {
  mlir::MLIRContext context;
  context.getOrLoadDialect<mlir::north_star::NorthStarDialect>();

  mlir::north_star::NorthStarDialect::sayHello();

  return 0;
}
```

**但是仅有这个main.cpp是完全不够的，还必须让他知道sayHello这个函数在哪里**

这部分内容来自你写的 **NorthStarDialect.cpp** 文件：

```c++
// NorthStarDialect.cpp
#include "Dialect/NorthStar/IR/NorthStarDialect.h"
#include "Dialect/NorthStar/IR/NorthStarDialect.cpp.inc"

using namespace mlir;
using namespace mlir::north_star;

void NorthStarDialect::initialize() {
  llvm::outs() << "initializing " << getDialectNamespace() << "\n";
}

NorthStarDialect::~NorthStarDialect() {
  llvm::outs() << "destroying " << getDialectNamespace() << "\n";
}

void NorthStarDialect::sayHello() {
  llvm::outs() << "Hello in " << getDialectNamespace() << "\n";
}
```

这个 `.cpp` 文件里实现了：

- `initialize()`：注册算子
- `sayHello()`：打印消息
- 析构函数

如果你在 CMake 里 **只编译 main.cpp**，而不链接 `NorthStarDialect.cpp`，会出现报错

```bash
undefined reference to `mlir::north_star::NorthStarDialect::sayHello()`

```

因为在用这个函数，但你没有告诉编译器“在哪里能找到它的定义”。

**因此这里link就用到了，链接其他c++文件到主程序里**

在cmake里这样写：

```c++
add_library(MLIRNorthStarDialect2
  src/Dialect/NorthStar/IR/NorthStarDialect.cpp
  ${CMAKE_CURRENT_BINARY_DIR}/include/Dialect/NorthStar/IR/NorthStarDialect.cpp.inc
  # 还有别的文件，比如op定义
)

add_executable(CH-2
  src/ch2/main.cpp
)

target_link_libraries(CH-2
  MLIRNorthStarDialect2
)

这里把main.cpp文件编译成可执行文件，同时利用link把MLIRNorthStarDialect2这个target连接到CH-2，这个MLIRNorthStarDialect2就是类似另外的c++文件的编译结果
```



**问题：主程序有#include，为什么还要link**

```c++
//include 只是“声明”，不是“定义”
// main.cpp
#include "NorthStarDialect.h"

int main() {
  NorthStarDialect::sayHello();  //
}

```

 `#include "NorthStarDialect.h"` 的作用是：

告诉编译器：“我会调用这个类/函数，”编译器就能检查语法：“参数对不对，函数存不存在”，但它并**没有告诉编译器**这个函数是在哪里实现的！

```c++
// main.cpp
#include "NorthStarDialect.h"

int main() {
  NorthStarDialect::sayHello(); // 声明是知道的
}

//但 sayHello() 真正的代码在另一个文件里：
// NorthStarDialect.cpp
void NorthStarDialect::sayHello() {
  std::cout << "Hello in NorthStar!" << std::endl;
}

//编译器单独编译 main.cpp 时，它只知道这个函数“存在”（因为头文件声明了），但不知道怎么实现它，所以需要链接
```

**（7）上面add_library是做什么的**

**创建一个名为 `MLIRNorthStarDialect2` 的“库 target”**，并把括号里的 `.cpp` 文件都**编译进去**，变成 `.o`（目标文件），最后打包成 `.a` 或 `.so` 或隐式静态库。

```
add_library(MLIRNorthStarDialect2
  src/Dialect/NorthStar/IR/NorthStarDialect.cpp
  ${CMAKE_CURRENT_BINARY_DIR}/include/Dialect/NorthStar/IR/NorthStarDialect.cpp.inc
)

```

| 参数                                             | 说明                                                         |
| ------------------------------------------------ | ------------------------------------------------------------ |
| `MLIRNorthStarDialect2`                          | 这是目标名（Target Name），其他地方用 `target_link_libraries(...)` 就是链接它 |
| `src/Dialect/...cpp`                             | 普通的源代码，包含 `Dialect` 的实际实现，比如 `注册 dialect`、`type/attr/op` 定义 |
| `${CMAKE_CURRENT_BINARY_DIR}/include/...cpp.inc` | 由 TableGen 自动生成的 `.inc` 文件，比如 `NorthStarOps.td` 生成的 `...cpp.inc`，里面定义了 op 的构造、打印、解析等函数实现 |

**（8）target和可执行文件之间有什么区别   ----可执行文件属于target的一种**

| 概念          | 说明                                                         |
| ------------- | ------------------------------------------------------------ |
| `target`      | 是 CMake 概念，表示一个“构建目标”，可以是一个库、一个可执行程序、一个测试模块等 |
| 可执行文件    | 是一种特定类型的 target，**编译完可以直接运行**，如 `main.exe`、`./my_program` |
| 库（Library） | 也是一种 target，但它不能运行，只能被别人“链接”来用，提供函数、类等功能 |

比如我们前面用到了可执行文件和library都是一种target

```
# 构建一个静态库（target）
add_library(MyMathLib
  Math.cpp
)

# 构建一个可执行文件（target）
add_executable(MyMainProgram
  main.cpp
)

# 链接这个库进主程序
target_link_libraries(MyMainProgram MyMathLib)

```

构建完成后的结果可能是：

```
build/
├── libMyMathLib.a         <-- 这是 MyMathLib target 生成的库
└── MyMainProgram          <-- 这是可执行文件 target，用户运行的程序
```

| 特性            | 库（Library Target）        | 可执行文件（Executable Target） |
| --------------- | --------------------------- | ------------------------------- |
| 是否能单独运行  | ❌ 否                        | ✅ 是                            |
| 常用 CMake 命令 | `add_library()`             | `add_executable()`              |
| 通常产物后缀    | `.a`, `.so`, `.dll`, `.lib` | `.out`, `.exe`, 无后缀（Unix）  |

**（9）代码解释  涉及方言注册、添加至上下文、方言加载**

```c++
void CH2() {
  mlir::DialectRegistry registry;
```

（1） `mlir::DialectRegistry registry;`

- 这是 **MLIR 的“方言注册器”**，下面详细讲，这个就像是空插排，定义的dialect就像是新电器，可以把电器插到插排注册

（2）`mlir::MLIRContext context(registry);`

`MLIRContext` 是 **管理整个 MLIR 编译过程中的所有数据结构的上下文**。

它必须知道有哪些方言（dialect），所以我们把 `registry` 传进去，确保你自定义的方言也能被加载。

（3） `auto dialect = context.getOrLoadDialect<mlir::north_star::NorthStarDialect>();`

这是关键的一句，拆解：

#### ✅ `getOrLoadDialect<T>()`：

- 是 `MLIRContext` 提供的模板方法。
- 用于获取指定类型的方言指针：
	- 如果之前加载过，直接返回；
	- 没加载过，则加载（Load），然后返回。

auto就是一个c++的关键字，自动推算类型，这里获取到的肯定是`NorthStarDialect *`这个指针类型



**（10）方言注册机 `mlir::DialectRegistry`**

*一步步来怎么注册？*

```c++
//1、先创建一个DialectRegistry对象，相当于一个空插排
mlir::DialectRegistry registry;
//2、往注册机加要用到的Dialect，这就是注册
//相当于告诉mlir我要用这个方言
registry.insert<mlir::north_star::NorthStarDialect>();

//也可以注册多个官方方言
registry.insert<mlir::arith::ArithDialect,
                mlir::func::FuncDialect,
                mlir::tensor::TensorDialect>();

//3、把注册机交给MLIRContext使用
mlir::MLIRContext context(registry);
```

*为什么我们上面没有insert？因为我定义的Dialect类用了宏*

`MLIR_DECLARE_EXPLICIT_TYPE_ID` 和 `MLIR_DEFINE_EXPLICIT_TYPE_ID`

```c++
//通常你会在 NorthStarDialect.h 中看到这样的宏：
#include "mlir/IR/Dialect.h"

namespace mlir {
namespace north_star {

class NorthStarDialect : public mlir::Dialect {
public:
  explicit NorthStarDialect(mlir::MLIRContext *context);

  static llvm::StringRef getDialectNamespace() { return "northstar"; }

  // 宏：用于注册 TypeID，支持自动 Dialect 注册
  MLIR_DECLARE_EXPLICIT_TYPE_ID(NorthStarDialect)
};

} // namespace north_star
} // namespace mlir




//然后会在 NorthStarDialect.cpp 中定义它：
MLIR_DEFINE_EXPLICIT_TYPE_ID(mlir::north_star::NorthStarDialect)

//这样就不需要insert了
```

```c++
//当我调用下面这句代码时

//那么MLIR会触发一定的机制自动加载并注册这个方言
```
