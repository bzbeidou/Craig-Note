#### 在编译TPU-MLIR整个项目的时候CPU会爆掉

当编译的时候，如果没有限制编译进程，系统会同时启动几十上百个编译进程

在 **多核 CPU + 没有限制资源** 的情况下，Docker + WSL 会疯狂拉满所有核心（100% 占用），从而出现：（如果是用的docker）

CPU 飙升；

VmmemWSL 占用极高； Docker 与 VSCode 终端链接断开（实质是 Docker 卡死）。

**怎么解决？ 限制编译进程数量就可以了**

ninja可以通过`-j`参数来限制并行线程数，如下

```bash
cmake --build . -- -j4
```

意思是：只允许同时编译 4 个文件。

注意：

> - `--` 之后的参数是传递给 **ninja** 的；
>- 如果不写 `-j`，ninja 默认使用所有可用核心（可能 16、24 个！）

因为我们为了统一就是直接用的`cmake --build .`命令，这个底层会自动调用ninja命令，然后我们还想用ninja的 `-j4`参数，那么就用`--`来将这个`-j4`选项传到ninja里，就相当于`ninja -j4`了

**一些等价写法：**

| 命令                         | 含义                               |
| ---------------------------- | ---------------------------------- |
| `cmake --build .`            | 默认并行（可能占满全部CPU）        |
| `cmake --build . -- -j4`     | 限制 Ninja 使用 4 个线程           |
| `ninja -j4`                  | 直接调用 Ninja，同样效果           |
| `cmake --build build -- -j2` | 指定在 build 目录中构建，2线程并行 |
