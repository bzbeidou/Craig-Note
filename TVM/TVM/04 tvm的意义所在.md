#### 引

#### 1、TVM的适用范围

1. **必须有硬件抽象层**
	- TVM 能生成 kernel 的前提是：硬件必须提供**可编程接口或抽象层**。
		- CPU → LLVM 后端
		- GPU → CUDA / PTX / ROCm
		- FPGA → HLS / OpenCL
	- 闭源 TPU、ASIC 等没有开放可编程接口的硬件 **TVM 不能直接使用**。
2. **并非直接“通吃所有硬件”**
	- 如果硬件完全封闭，没有公开抽象，TVM 就没法做自动调度。
	- 所以 TVM 的跨平台能力有前提，不是万能的。



#### 2、真正意义

**TVM的提出时间是早于MLIR的，甚至MLIR的一些理念是由TVM启发的，TVM的真正意义在于提出了一套系统化、自动化、高性能计算的编译器思路**

**（1） 统一 AI 编译器体系**

- TVM 提出了 **高层 IR → 张量表达式 → 调度 → kernel 生成** 的标准流程；
- 以前各个框架（TensorFlow、Caffe、Theano）优化手段零散、难以跨平台；
- TVM 让算子优化和图优化**可复用、可组合、可自动化**。

**（2） 自动化调度和性能搜索**

- TVM 的 AutoTVM / Ansor 可以自动探索最佳 kernel 调度，不再完全依赖人工经验；
- 对 CPU/GPU/FPGA 等开放硬件，TVM 可以生成**性能接近人工调优的 kernel**；
- 大幅降低了新算子开发成本。

**（3） 为未来硬件适配打基础**

- 只要硬件开放可编程接口，TVM 就可以快速适配，不用重写算子库；
- 这为 AI 编译器研究和跨平台部署提供了“通用模板”；
- 也促使硬件厂商思考如何开放抽象层，以便框架/编译器能高效利用。



#### 3、算子逻辑表达和具体计算分离思路的发扬

**我在学TPU-MLIR所以对这种想法很熟悉，甚至自然地就接受了，但是是TVM将这种思想给发扬的**

**（1）表达层**（High-Level Representation）

- 只描述“我要做什么”，不关心**怎么执行**。
- 例如：卷积、矩阵乘法、ReLU 等算子的数学逻辑。
- 在 TVM 里，这对应 **TE（Tensor Expression）** 层。

**（2）计算层 / 调度层**（Schedule / Kernel Generation）

- 描述“如何执行”，即具体计算、循环展开、线程调度、内存布局等。
- 在 TVM 里，这对应 **Schedule + Lowered IR → LLVM/CUDA PTX**。

> 🔹 核心理念：**算子表达与执行调度分离** → 可以让同一个表达式生成不同硬件上最优实现。
