#### 引

TVM和TPU-MLIR之间到底有什么区别和联系呢，他们是一个同级的概念吗



**记住一句话：tvm就是一个优化写kernel的过程，让人力写kernel变得更简单，但是这个写kernel的过程是针对使用CUDA这样的抽象接口写kernel的过程，而不是直接调用指令写kernel的过程**



#### 1、TVM就像AI一样，可以自动写代码

告诉它：“我要一个卷积算子，跑在 GPU 上。”
 它就会：

- 自己推算怎么展开循环

- 自己决定线程划分

- 自己生成 CUDA 代码

- 自己调参测性能

	**最后产出一个性能最优的 kernel，自动生成的这个kernel甚至可以经过人工优化之后放到cuDNN里作为标准的kernel计算**

#### 2、TPU-MLIR则就是传统的方法，去调用算呢个提供的算子库

会自己写算子，而是：

- 接收 PyTorch / ONNX 模型；
- 把计算图拆成算子；
- 对图做优化（融合、量化、常量折叠等）；
- 然后根据硬件支持情况，把每个算子映射到厂商已有的算子实现；
- 最终生成硬件指令流（调用厂商库中的 kernel）。



**为什么不开发属于自己的CUDA呢？ **

- 这是很耗费时间人力的一件事，如果寒武纪、算能这种都能推出自己的CUDA，那么TVM肯定能应用在这些对应的芯片上。同时还要考虑生态的问题，像pytorch这种框架已经接入了CUDA，所以生态也是问题。



#### 3、TVM的关键

经过前面的分析我们已经大致明白了TVM为什么能将模型运行在各种硬件上，但是不包括bm1684这种芯片上

**是因为他们底层指令之上还开发了一层，比如 LLVM IR 或者 CUDA，但是其他的芯片没有**

CPU 路径：

- TVM 把计算图经过优化后（融合、张量表达式化），会降低成 **LLVM IR**。
- 然后通过 **LLVM** 后端生成目标 CPU 的机器码（x86 / ARM / RISC-V）。
- 所以 TVM **不需要厂商算子库**，只要 LLVM 支持该 CPU 指令集即可。

这就是 **TVM 能编译到 CPU 的核心原因：LLVM 提供了底层桥梁**。

 GPU 路径：

- GPU 的底层 API 是 **CUDA**（NVIDIA）或 **ROCm**（AMD）。
- TVM 在内部可以**生成 CUDA 源代码** 或者 **PTX（GPU汇编）代码**。
- 也就是说，TVM 自己“充当了编译器”，可以生成 GPU 运行的代码，不依赖 cuDNN。

> cuDNN 本质上是英伟达手写和调优的算子库；
>  TVM 则是自动搜索最优实现（AutoTVM / Ansor），直接生成 CUDA 内核。
